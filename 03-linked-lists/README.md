# 03. Linked Lists (связные списки)

## Суть в двух предложениях

Связный список — это цепочка узлов, где каждый знает только своего соседа,
поэтому до нужного места нельзя «прыгнуть» по индексу, зато вставка и удаление
рядом с уже найденным узлом стоят O(1). Почти все задачи на списки сводятся
к аккуратной **перестановке ссылок**: нужно не потерять остаток списка,
не создать цикл и не споткнуться о голову, у которой нет предыдущего узла.

Алгоритмы здесь простые, а ошибки — механические. Поэтому главный навык темы —
дисциплина: рисовать стрелки, называть указатели по их роли и проверять края.

## Как узнать паттерн

- на входе прямо дан **узел-голова** (`head`), а не массив;
- требуют изменить порядок или состав элементов **на месте, с памятью O(1)**;
- речь про позицию **«с конца»** или **«середину»**, а длина заранее неизвестна;
- нужно спроектировать структуру, где элементы часто **переезжают** с места
  на место или удаляются из середины за O(1) (кэши, очереди, упорядоченные
  по давности);
- в условии встречаются слова «разверни», «склей», «вырежи», «сплющь».

Контрпример: нужен частый доступ по номеру («дай 500-й элемент») или бинарный
поиск. В списке это O(n) на каждое обращение — берите массив. И наоборот: если
задачу на списках можно решить, выгрузив значения в массив, это рабочий первый
ответ, но обычно от решения требуют O(1) памяти.

## Что нужно знать про сложность

| Операция | Односвязный | Двусвязный | Массив (`list`) |
|---|---|---|---|
| доступ по номеру | O(n) | O(n) | O(1) |
| поиск по значению | O(n) | O(n) | O(n) |
| вставка/удаление в начале | O(1) | O(1) | O(n) |
| вставка после известного узла | O(1) | O(1) | O(n) |
| удаление известного узла | O(n)* | O(1) | O(n) |

\* В односвязном списке для удаления нужен **предыдущий** узел, а узнать его
можно только проходом от головы. Двусвязный список хранит `prev` — за это
платим вторым указателем в каждом узле и вдвое большим числом стрелок,
которые надо не забыть переставить.

Узел в этой теме устроен так (лежит в [linked_lists_helpers.py](linked_lists_helpers.py)):

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next
```

## Четыре приёма

### 1. Pointer rewiring (перестановка ссылок)

Идём по списку и меняем `next` у текущего узла. Правило одно: **прежде чем
перезаписать ссылку, сохрани то, на что она указывала** — иначе остаток
списка станет недостижим.

```text
до:      prev      curr ──► following ──► ...
шаг:     prev ◄── curr      following ──► ...
```

```python
prev, curr = None, head
while curr is not None:
    following = curr.next     # 1. спасти остаток
    curr.next = prev          # 2. переставить стрелку
    prev, curr = curr, following   # 3. сдвинуться
```

Когда: разворот списка целиком или кусками, перестановка пар, палиндром.

### 2. Dummy node (фиктивный узел)

Перед головой ставится узел-пустышка. Теперь у **каждого** настоящего узла
есть предыдущий, и случаи «удаляем голову», «вставляем в пустой список»
перестают быть особыми. В конце возвращаем `dummy.next`, а не `head`.

```text
dummy ──► head ──► ... ──► tail ──► None
```

```python
dummy = ListNode(0, head)
before = dummy
while before.next is not None:
    if надо_удалить(before.next):
        before.next = before.next.next
    else:
        before = before.next
return dummy.next
```

Когда: удаление узлов, слияние списков, сборка нового списка по частям.
В двусвязном списке тот же приём даёт два стража — в начале и в конце.

### 3. Two pointers on a list (два указателя на списке)

Длина неизвестна, назад идти нельзя — зато можно пустить два указателя
с разными правилами движения. Частые варианты:

- **с разрывом**: первый уходит на k шагов, потом идут в ногу —
  когда первый в конце, второй в k шагах от конца;
- **с разной скоростью**: быстрый делает два шага, медленный один —
  когда быстрый в конце, медленный в середине (подробно — тема 04);
- **со сменой списка**: дойдя до конца своего списка, указатель переходит
  на чужой — так выравнивается разница длин;
- **хвост и догоняющий**: один держит конец списка, второй идёт от головы
  и дописывает в конец новые куски.

```python
lead = trail = head
for _ in range(k):
    lead = lead.next
while lead is not None:
    lead, trail = lead.next, trail.next
```

### 4. Hash map + doubly linked list (хеш-таблица + двусвязный список)

Список хранит **порядок**, но не умеет искать. Хеш-таблица умеет искать,
но не хранит нужный порядок. Вместе: таблица `ключ → узел` за O(1) находит
узел, а двусвязный список за O(1) вырезает его и переставляет.

```text
таблица:   7 ─┐        9 ─┐
              ▼           ▼
старые ⇄ [7: 71] ⇄ [9: 90] ⇄ свежие
```

Когда: LRU/LFU-кэши, «очередь с удалением из середины», любой порядок,
который меняется при каждом обращении.

### Развернуть список

**Условие.** Дана голова односвязного списка. Развернуть его на месте
и вернуть новую голову.

**Идея (итеративно).** Значения никуда не двигаем — разворачиваем стрелки.
Идём слева направо и каждому узлу велим смотреть на предыдущий. Нужны три
ссылки: `prev` (уже развёрнутая часть), `curr` (кого разворачиваем) и
`following` (остаток, который нельзя потерять).

**Почему корректно.** Инвариант: перед каждой итерацией `prev` — голова
полностью развёрнутого префикса, `curr` — голова нетронутого остатка, и эти
части не связаны. Когда `curr` становится `None`, остаток пуст, а значит
`prev` — голова всего развёрнутого списка.

```text
список: 4 → 9 → 2 → 7

после шага   развёрнутая часть (от prev)   curr
    1        4                             9
    2        9 → 4                         2
    3        2 → 9 → 4                     7
    4        7 → 2 → 9 → 4                 None  → ответ: prev
```

**Идея (рекурсивно).** Доверяем рекурсии развернуть всё после головы. Тогда
старый сосед головы оказался в самом конце развёрнутой части, и `head.next`
всё ещё указывает на него. Остаётся две строки:

```python
head.next.next = head   # прицепить голову в конец
head.next = None        # и оборвать старую стрелку, иначе цикл
```

Рекурсия короче, но держит n кадров на стеке: память O(n), а в CPython
ещё и лимит глубины около 1000. Полезно знать оба
варианта; в рабочем коде выбирают итеративный.

### Удалить k-й узел с конца

**Условие.** Удалить k-й с конца узел (k = 1 — это хвост) и вернуть голову.
В списке есть хотя бы один узел. В нашем решении, если k больше длины,
список возвращается как есть — в условии этот случай стоит уточнять отдельно.

**Идея.** Решение «в лоб» — два прохода: посчитать длину n, затем дойти
до узла с номером n − k. Один проход получается, если запустить двух
указателей с разрывом в k шагов. Разведчик уходит вперёд на k узлов, затем оба
идут в ногу. Когда разведчик встаёт на хвост, отстающий стоит ровно **перед**
удаляемым узлом — а для удаления нужен именно предыдущий.

**Зачем dummy.** Если удалять надо голову, «предыдущего» у неё нет.
Оба указателя стартуют с фиктивного узла, и случай перестаёт быть особым.

```text
dummy → 5 → 8 → 3 → 6 → 1,  k = 2

разведчик уходит на 2 шага:   scout = 8    before = dummy
идут в ногу:                  scout = 3    before = 5
                              scout = 6    before = 8
                              scout = 1    before = 3   ← scout на хвосте, стоп

before.next = before.next.next   → вырезали 6
ответ: 5 → 8 → 3 → 1
```

**Почему разрыв именно такой.** Между `before` и `scout` всё время k стрелок.
Если `scout` — последний узел (1-й с конца), то `before` — (k+1)-й с конца,
то есть сосед слева от k-го.

### Точка пересечения двух списков

**Условие.** Два односвязных списка могут «слиться»: начиная с некоторого
узла у них общий хвост. Вернуть первый общий узел или `None`. Сравниваются
**сами узлы**, а не значения: два разных узла с числом 5 — не пересечение.

**Идея первая — множество.** Сложить узлы первого списка в `set`, пройти
по второму до первого узла из множества. O(n + m) по времени, O(n) по памяти.

**Идея вторая — O(1) памяти.** Мешает разная длина «личных» частей: если бы
списки были равной длины, хватило бы идти по ним параллельно. Выравниваем
пути так: каждый указатель проходит свой список, а затем **чужой**. Оба
маршрута имеют длину n + m и заканчиваются одним и тем же общим хвостом,
значит, на первый общий узел указатели наступят одновременно.

```text
A: 2 → 7 ─┐
          ├→ 6 → 5
B: 9 → 4 → 1 → 3 ─┘

шаг   a      b
 0    2      9
 1    7      4
 2    6      1
 3    5      3
 4    None   6      ← a дошёл до конца A
 5    9      5      ← и перешёл на B
 6    4      None
 7    1      2      ← b перешёл на A
 8    3      7
 9    6      6      ← один и тот же узел: ответ
```

**Если пересечения нет.** Оба указателя после n + m шагов одновременно
становятся `None`, условие `a is not b` перестаёт выполняться, и функция
возвращает `None` без отдельной ветки. Для этого переходить на чужой список
надо, когда указатель **сам** стал `None`, а не когда `next` пуст — иначе
`None` не наступит никогда и цикл будет бесконечным.

### LRU-кэш

**Условие.** Кэш ёмкости `capacity` с двумя операциями за O(1):
`get(key)` возвращает значение или −1, `put(key, value)` добавляет или
обновляет пару. При переполнении вытесняется ключ, которым **дольше всего
не пользовались**; «пользоваться» — это и `get`, и `put`.

**Идея.** Нужны две способности сразу:

- найти запись по ключу за O(1) — это хеш-таблица;
- держать записи в порядке давности и за O(1) переносить любую в «свежий»
  конец — это двусвязный список.

Таблица хранит `ключ → узел списка`. Любая операция сводится к двум
примитивам: `_unlink(узел)` — вырезать, `_push_back(узел)` — вставить
в свежий конец. Вытеснение — вырезать узел у старого конца.

**Три детали, на которых обычно спотыкаются.**

1. Список именно **двусвязный**: чтобы вырезать узел, нужен его левый сосед,
   а в односвязном до него O(n).
2. В узле лежит не только значение, но и **ключ**: при вытеснении мы держим
   в руках узел и должны удалить соответствующую запись из таблицы.
3. Два **стража** по краям избавляют от проверок «а вдруг это первый/последний
   узел» — у настоящего узла всегда есть оба соседа.

```text
capacity = 2                 порядок: давние → свежие

put(7, 70)                   [7:70]
put(3, 30)                   [7:70, 3:30]
get(7)  → 70                 [3:30, 7:70]     7 переехал в свежий конец
put(5, 50)                   [7:70, 5:50]     вытеснен 3
get(3)  → -1                 [7:70, 5:50]
put(7, 71)                   [5:50, 7:71]     обновление тоже «использование»
put(9, 90)                   [7:71, 9:90]     вытеснен 5, а не 7
get(5)  → -1                 [7:71, 9:90]
```

В Python ту же задачу решает `collections.OrderedDict` с `move_to_end` и
`popitem(last=False)` — внутри он устроен точно так же. Знать о нём
полезно, но смысл задачи — в ручной реализации. В тестах наш кэш сверяется
с эталоном на `OrderedDict` — причём не только ответы `get`, но и весь
порядок записей после каждой операции.

### Список-палиндром

**Условие.** Проверить, что значения односвязного списка читаются одинаково
слева направо и справа налево. Пустой список и один узел — палиндромы.

**Идея.** В массиве хватило бы встречных указателей (тема 01), но в списке
нельзя идти назад. Выход — развернуть **вторую половину**, тогда «чтение
с конца» превращается в обычный проход вперёд.

1. Быстрый и медленный указатели: когда быстрый упёрся в конец, медленный
   стоит на начале второй половины (при нечётной длине — на центральном узле).
2. Разворачиваем список от медленного указателя — готовой функцией из первой задачи.
3. Идём двумя указателями от головы и от нового начала второй половины,
   сравниваем значения, пока вторая половина не кончится.
4. Разворачиваем вторую половину обратно — возвращаем вход в исходный вид.

```text
3 → 8 → 5 → 8 → 3

поиск середины:   slow = 8, fast = 5
                  slow = 5, fast = 3   ← fast на хвосте, стоп; slow на центре

разворот от slow: первая половина    3 → 8 → 5
                  вторая половина    3 → 8 → 5     (узел 5 общий, он теперь хвост)

сравнение:        3 = 3, 8 = 8, 5 = 5  → палиндром
```

Для чётной длины, например `3 → 8 → 8 → 3`, медленный остановится на второй
восьмёрке, вторая половина после разворота — `3 → 8`, сравнений будет два.

**Почему шаг 4 важен.** Функция с названием «проверить» не должна менять
данные. Если список после вызова оказывается разорванным пополам, это
побочный эффект, о котором вызывающий код не догадывается. Поэтому список стоит
восстанавливать, даже если условие этого прямо не требует.

### Сплющить многоуровневый список

**Условие.** У каждого узла, кроме `next`, есть `child` — голова вложенного
списка (или `None`); у вложенных узлов тоже могут быть дети. Нужно на месте
превратить структуру в обычный одноуровневый список, где сначала идут все
узлы верхнего уровня, за ними — все узлы второго уровня и так далее.
Все `child` в итоге должны стать `None`.

**Идея.** Порядок «по уровням» — это обход в ширину, которому нужна очередь.
Но очередь уже есть — это сам список. Находим его хвост, а затем идём от
головы указателем `scan`: встретив узел с ребёнком, дописываем дочерний ряд
в хвост и сдвигаем хвост в новый конец. До дописанных узлов `scan` со
временем дойдёт сам и точно так же обработает уже их детей.

```text
1 → 2 → 3 → 4
    |       |
    5 → 6   7
    |
    8 → 9

scan = 2:  1 → 2 → 3 → 4 → 5 → 6                    хвост = 6
scan = 4:  1 → 2 → 3 → 4 → 5 → 6 → 7                хвост = 7
scan = 5:  1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 9        хвост = 9
```

**Почему O(n), хотя циклов два.** Хвост двигается только вперёд и проходит
каждый узел не больше одного раза; `scan` — тоже. Итого не больше 2n шагов.
Память O(1): очередь не заводили.

**Вариант «в глубину».** Если дочерний ряд должен встать **сразу после
родителя** (как в LeetCode 430), меняется одно действие: ищем хвост дочернего
ряда, пришиваем к нему `node.next`, а сам ряд ставим на место `node.next`.
На том же примере получится `1 → 2 → 5 → 8 → 9 → 6 → 3 → 4 → 7`.
Какой порядок нужен, всегда стоит уточнять: из слова «flatten» это не следует.

## Типичные ошибки

- **Потерянный остаток.** `curr.next = prev` до того, как сохранили
  `curr.next`. Остаток списка недостижим, цикл завершается после первого узла.
- **Цикл из двух узлов.** В рекурсивном развороте забыли `head.next = None`:
  два узла указывают друг на друга, и любой обход зависает.
- **Вернули `head` вместо `dummy.next`.** Если удалили голову, `head`
  указывает на выброшенный узел — и старый список «воскресает».
- **Обращение к `.next` у `None`.** Перед `node.next.next` убедитесь, что
  существует и `node`, и `node.next`. Для быстрого указателя условие цикла —
  `fast is not None and fast.next is not None`, именно в таком порядке.
- **Сдвиг на единицу в «k-м с конца».** Остановиться нужно **перед**
  удаляемым узлом. Проверьте на k = 1 и на k, равном длине списка.
- **Сравнение значений вместо узлов** в задаче о пересечении: нужно `is`,
  а не `==` и тем более не `a.val == b.val`.
- **Переход на чужой список по условию `next is None`** — бесконечный цикл
  для непересекающихся списков.
- **LRU: обновление без «освежения».** `put` для существующего ключа обязан
  переносить его в свежий конец. И обратная ошибка: вытеснили узел из списка,
  но забыли удалить ключ из таблицы.
- **Забытый `child = None`** при сплющивании: список выглядит правильно при
  проходе по `next`, но формально остаётся многоуровневым.
- **Рекурсия на длинном списке.** В Python это `RecursionError` уже на
  тысячах узлов.
