# 05. Sliding Windows (скользящее окно)

## Суть в двух предложениях

Окно — это непрерывный кусок массива или строки между указателями `left`
и `right`, которые двигаются **только вправо**. Вместо того чтобы для каждой
подстроки считать всё заново, мы храним **состояние окна** (сумму, частоты,
множество символов) и за O(1) подправляем его, когда один элемент входит
справа, а другой выходит слева.

Это частный случай Two Pointers (тема 01): оба указателя идут в одну сторону,
но интересны не сами позиции, а то, что лежит **между** ними.

## Как узнать паттерн

- в условии есть слова **«подстрока»** или **«подмассив»** — то есть нужен
  непрерывный участок, а не произвольная выборка элементов;
- ищут **самый длинный / самый короткий** участок с каким-то свойством либо
  **количество** участков заданной длины;
- свойство участка выражается через то, что легко обновлять по одному
  элементу: сумма, счётчики символов, число различных значений;
- свойство **монотонно**: если участок «сломался», то удлинение вправо его не
  починит, а укорачивание слева рано или поздно починит;
- наивное решение — перебор всех пар (начало, конец), O(n²) или O(n³).

Контрпример: «самый длинный подмассив с суммой ровно `target`», когда в массиве
есть **отрицательные числа**. Расширение окна может и увеличить сумму,
и уменьшить — монотонности нет, и непонятно, какую границу двигать. Здесь нужны
префиксные суммы с хеш-таблицей (тема 10). Второй контрпример —
«подпоследовательность»: элементы идут не подряд, окном их не накрыть.

## Почему это O(n)

В коде переменного окна есть вложенный `while`, но это не O(n²). Каждый элемент
**один раз входит** в окно (когда до него доходит `right`) и **не более одного
раза выходит** (когда его проходит `left`). Указатели назад не возвращаются,
поэтому суммарно они делают не больше 2n шагов.

Оценка держится на втором условии: **обновление состояния должно стоить O(1)**.
Если при каждом сдвиге пересчитывать что-то по всему окну (например,
`max(window)` или сравнение двух частотных таблиц), множитель вернётся.

## Два приёма

### 1. Fixed window (окно фиксированной длины)

Длина окна `width` известна заранее — из условия или из входных данных.
Окно едет по строке как рамка: на каждом шаге один элемент входит, один выходит.

```text
s = [ a  b  c  d  e  f  g ]      width = 3
      └─────┘                    окно [0..2]
         └─────┘                 вошёл d, вышел a
            └─────┘              вошёл e, вышел b
```

```python
state = пустое_состояние()
for right in range(len(data)):
    добавить(state, data[right])
    left = right - width            # элемент, который только что выпал из рамки
    if left >= 0:
        убрать(state, data[left])
    if right >= width - 1 and подходит(state):   # рамка заполнена целиком
        учесть_ответ()
```

Когда: анаграммы и перестановки в строке, максимальная сумма `k` подряд идущих
элементов, скользящее среднее, «есть ли дубликат на расстоянии не больше `k`».

### 2. Dynamic window (окно переменной длины)

Длина заранее неизвестна — её и ищем. `right` расширяет окно на каждом шаге,
`left` догоняет, только когда окно перестало удовлетворять условию.

```text
расширяем, пока всё хорошо:        [ x  y  z ] w  ...
                                     ^left  ^right

окно сломалось — поджимаем слева:     x [ y  z  w ] ...
                                          ^left  ^right
```

```python
left = 0
best = 0
for right in range(len(data)):
    добавить(state, data[right])
    while not допустимо(state):        # сжимаем, пока окно не починится
        убрать(state, data[left])
        left += 1
    best = max(best, right - left + 1)  # здесь окно гарантированно допустимо
```

У шаблона есть две полезные модификации, обе встретятся в задачах ниже:

- **прыжок вместо сжатия** — если известно, *куда* должна встать левая граница,
  `while` заменяется одним присваиванием;
- **сдвиг вместо сжатия** — если нужна только максимальная длина, окно можно
  вообще не уменьшать: `while` заменяется на `if`, и окно едет дальше с рекордной
  длиной, пока не найдётся повод вырасти.

Для задач на **самое короткое** окно шаблон зеркальный: ответ обновляется
*внутри* `while`, пока окно ещё допустимо, и сжатие идёт до первой поломки.

### Сколько подстрок — анаграммы заданной строки

**Условие.** Даны строки `s` и `t` из строчных латинских букв. Посчитать,
сколько подстрок `s` являются анаграммами `t`, то есть состоят из тех же букв
в тех же количествах. Одинаковые подстроки на разных позициях считаются отдельно.
Если `t` длиннее `s`, ответ 0.

**Идея.** Анаграмма `t` обязана иметь длину `len(t)` — значит, окно
фиксированное. «Те же буквы в тех же количествах» — это равенство частотных
таблиц, а таблицу окна легко обновлять: вошла буква — `+1`, вышла — `-1`.

Простой вариант — две таблицы по 26 ячеек и сравнение на каждом шаге, O(26·n).
В решении сделан ещё один шаг: хранится одна таблица **долгов** `debt`
(сколько каждой буквы окну не хватает до анаграммы; минус — избыток) и счётчик
`unsettled` — у скольких букв долг ненулевой. Окно является анаграммой ровно
тогда, когда `unsettled == 0`, и эта проверка стоит O(1) при любом алфавите.

**Почему не нужно отдельно проверять, что окно заполнено.** Сумма всех долгов
равна `len(t)` минус текущая длина окна. Пока окно короче, сумма положительна,
значит, хотя бы один долг ненулевой, и `unsettled == 0` не сработает.

**Почему не сортировка.** Сортировать каждое окно и сравнивать с `sorted(t)` —
это O(n · m log m). Так в тестах устроен эталонный перебор, но не решение.

```text
s = "tropotpor", t = "opt"            изначально debt = {o:1, p:1, t:1}

окно [0..2] "tro"   debt: p:+1 r:-1   → нет
окно [1..3] "rop"   debt: t:+1 r:-1   → нет
окно [2..4] "opo"   debt: t:+1 o:-1   → нет
окно [3..5] "pot"   все долги нулевые → +1
окно [4..6] "otp"   все долги нулевые → +1
окно [5..7] "tpo"   все долги нулевые → +1
окно [6..8] "por"   debt: t:+1 r:-1   → нет
                                итого: 3
```

Три анаграммы подряд получились не случайно: из окна вышла та же буква, что
и вошла, — таблица долгов не изменилась.

### Самая длинная подстрока без повторов

**Условие.** Найти длину самой длинной подстроки, в которой все символы
различны. Для пустой строки ответ 0.

**Идея.** Свойство монотонно: если в окне появился повтор, то любое расширение
вправо его сохранит, а починить окно можно, только убрав слева прежнее вхождение
повторившегося символа. Это в чистом виде переменное окно.

**Вариант 1 — множество.** Храним символы окна в `set`. Если новый символ уже
там, выбрасываем символы слева по одному, пока не выбросим его двойника.
Повтор в окне может быть только один — сам новый символ, потому что до его
прихода окно было чистым.

```text
s = "moloko"

right=0 'm'                    окно "m"     лучшее 1
right=1 'o'                    окно "mo"    лучшее 2
right=2 'l'                    окно "mol"   лучшее 3
right=3 'o'  выбросили m, o    окно "lo"    лучшее 3
right=4 'k'                    окно "lok"   лучшее 3
right=5 'o'  выбросили l, o    окно "ko"    лучшее 3
```

**Вариант 2 — таблица последних позиций.** Выбрасывая символы по одному, мы
ищем то, что можно было запомнить: где повторившийся символ встречался
в последний раз. Храним `last_seen: символ → индекс`, и левая граница
**прыгает** сразу на `last_seen[ch] + 1`. Внутренний цикл исчезает.

Тонкость: записи из таблицы не удаляются, поэтому в ней лежат и позиции левее
окна. Такая позиция — не повтор, и прыгать по ней нельзя, иначе граница поедет
**назад**. Отсюда условие `last_seen[ch] >= left`:

```text
s = "abba"

right=0 'a'                                      left=0  окно "a"    лучшее 1
right=1 'b'                                      left=0  окно "ab"   лучшее 2
right=2 'b'  last_seen=1 ≥ left → прыжок         left=2  окно "b"    лучшее 2
right=3 'a'  last_seen=0 < left → это не повтор  left=2  окно "ba"   лучшее 2
```

Без проверки на последнем шаге `left` стал бы равен 1, окно — `"bba"`,
а ответ — 3.

Асимптотика у вариантов одинаковая, O(n); второй просто делает один проход
вместо двух и не содержит вложенного цикла. Разумно начать
с множества, а таблицу рассматривать как улучшение. Оба решения лежат в одном файле.

### Самая длинная однородная подстрока после k замен

**Условие.** Однородная подстрока состоит из одного и того же символа.
Разрешено заменить не более `k` символов строки на любые другие. Найти
наибольшую длину однородной подстроки, которую можно так получить.

**Идея.** Сами замены делать не нужно. Чтобы превратить окно в однородное
дешевле всего, оставляем самый частый символ и меняем все остальные, поэтому

```text
нужно_замен = длина_окна − частота_самого_частого_символа
```

Окно допустимо, если `нужно_замен <= k`. Свойство монотонно: выбрасывая символ
слева, мы уменьшаем длину на 1, а наибольшую частоту — не больше чем на 1, так
что любая часть допустимого окна тоже допустима. Значит, подходит переменное окно
с таблицей частот.

**Где прячется лишний множитель.** Когда символ *входит*, наибольшая частота
обновляется за O(1): вырасти могла только частота вошедшего символа. А вот
когда символ *выходит*, честный максимум приходится искать по всей таблице —
O(A) на шаг. Так устроен вариант `..._shrinking`, и для алфавита из 26 букв это
вполне приемлемо. Но можно обойтись и без пересчёта.

**Почему окно можно не сжимать, а только сдвигать.** Нам нужно одно число —
рекордная длина. Окно короче рекорда ответ уже не улучшит, так что сжимать его
бессмысленно: достаточно тащить по строке рамку рекордной длины и ждать повода
её увеличить. Отсюда два изменения в шаблоне:

- вместо `while` — `if`: окно выросло на один символ, и если новая длина
  недопустима, один шаг `left` возвращает прежнюю длину;
- `top_count` — не частота в текущем окне, а **наибольшая частота, которая
  когда-либо встречалась**. При выходе символа она не уменьшается.

Устаревший `top_count` выглядит как ошибка, поэтому корректность стоит
доказать в обе стороны.

*Не завысим ответ.* Окно растёт только при условии `длина <= top_count + k`.
Пусть рекорд `top_count = f` был поставлен на некотором окне `W`: в нём `f`
одинаковых символов. Любое окно длины до `f + k`, накрывающее `W`, допустимо —
каждый лишний символ стоит не больше одной замены, а бюджета `k` на них хватает.
Значит, любая длина, до которой вырастает рамка, действительно достижима —
пусть даже не тем окном, на котором рамка стоит сейчас.

*Не упустим ответ.* `top_count` не меньше настоящей частоты в текущем окне,
поэтому проверка получается только **мягче** честной: окно, которое допустимо
на самом деле, она никогда не отвергнет. Отсюда инвариант: после каждого шага
рамка не короче самого длинного допустимого окна, которое заканчивается
в `right`. В самом деле, пусть это окно `[a..right]` длины `M`. Его часть
`[a..right−1]` тоже допустима, значит, по инварианту рамка перед шагом была
не короче `M − 1`. Если она уже не короче `M` — хорошо, рамка не уменьшается.
Если ровно `M − 1` — после прихода нового символа она совпадает с `[a..right]`,
проверка её пропускает, и рамка вырастает до `M`.

```text
s = "xxyzxxwx", k = 2

right=0 'x'  top=1  окно "x"        замен 1−1=0           растёт   длина 1
right=1 'x'  top=2  окно "xx"       замен 2−2=0           растёт   длина 2
right=2 'y'  top=2  окно "xxy"      замен 3−2=1           растёт   длина 3
right=3 'z'  top=2  окно "xxyz"     замен 4−2=2           растёт   длина 4
right=4 'x'  top=3  окно "xxyzx"    замен 5−3=2           растёт   длина 5
right=5 'x'  top=4  окно "xxyzxx"   замен 6−4=2           растёт   длина 6
right=6 'w'  top=4  окно "xxyzxxw"  замен 7−4=3 > k  →    сдвиг    окно "xyzxxw", длина 6
right=7 'x'  top=4  окно "xyzxxwx"  замен 7−4=3 > k  →    сдвиг    окно "yzxxwx", длина 6

ответ: len(s) − left = 8 − 2 = 6        ("xxyzxx" → "xxxxxx")
```

Посмотрите на последние два шага. В окне `"xyzxxw"` настоящая наибольшая
частота — 3, а `top` по-прежнему 4: само это окно недопустимо (ему нужно три
замены). Это нормально: рамка хранит **длину** рекорда, а не окно-рекордсмена.
Отсюда и ограничение приёма — если нужно вернуть саму подстроку, её границы
надо запоминать в момент роста либо пользоваться вариантом со сжатием.

## Типичные ошибки

- **Ошибка на единицу в длине.** Длина окна — `right - left + 1`. В фиксированном
  окне выпадает элемент с индексом `right - width`, а первое полное окно
  получается при `right == width - 1`.
- **Обновление ответа до починки окна.** В шаблоне на максимум `best`
  обновляется *после* `while`, когда окно снова допустимо; в шаблоне на
  минимум — *внутри* `while`.
- **Не убрать вышедший элемент из состояния.** Сдвинули `left`, а счётчик
  не уменьшили — окно в голове и окно в таблице разъехались. Ошибка тихая:
  код не падает, а отвечает неверно.
- **Сравнение множеств букв вместо частот** в задаче про анаграммы:
  `"aab"` и `"abb"` состоят из одних и тех же букв, но анаграммами не являются.
- **Забытая проверка `len(t) > len(s)`** и пустых строк.
- **Прыжок назад.** В варианте с `last_seen` без условия `>= left` граница
  уезжает влево на строках вида `"abba"`. Эквивалентная запись —
  `left = max(left, last_seen[ch] + 1)`.
- **Чистить `last_seen` при прыжке.** Незачем: это возвращает внутренний цикл,
  от которого прыжок как раз избавлял.
- **«Починить» `top_count`**, пересчитывая его при сдвиге. Код останется
  верным, но сложность вырастет до O(A·n), а смысл приёма потеряется.
- **Вернуть окно из варианта без сжатия.** Рамка хранит рекордную длину,
  но стоять может на недопустимом участке — как подстроку её выдавать нельзя.
- **Окно там, где нет монотонности.** Отрицательные числа в задачах на сумму,
  условия вида «ровно k различных» без дополнительного трюка. Прежде чем писать
  код, спросите себя: «если окно сломалось, точно ли сдвиг `left` его чинит?»
