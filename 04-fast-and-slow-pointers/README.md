# 04. Fast and Slow Pointers (быстрый и медленный указатели)

## Суть в двух предложениях

Два указателя идут по одной и той же цепочке в одну сторону, но с разной
скоростью: медленный делает один шаг, быстрый — два. Полезную информацию несёт
**расстояние между ними**: на прямой дороге оно растёт предсказуемо (быстрый
в конце — медленный в середине), а на кольце быстрый неизбежно догоняет
медленного — так цикл обнаруживается без единого байта дополнительной памяти.

Приём известен как алгоритм Флойда, или «черепаха и заяц».

## Как узнать паттерн

- данные — **цепочка с единственным «следующим»**: односвязный список либо
  процесс вида `x → f(x)`, где следующее состояние полностью определяется текущим;
- спрашивают про **цикл**: есть ли он, где начинается, какой длины;
- нужна **позиция в долях длины** — середина, треть, — а длина заранее
  неизвестна и второй проход нежелателен;
- решение с множеством посещённых узлов очевидно, но просят **память O(1)**;
- список **нельзя изменять** (иначе посещённые узлы можно было бы просто помечать).

Контрпример: поиск цикла в произвольном графе, где у вершины несколько
исходящих рёбер. «Следующий шаг» там не единственный, указателю непонятно, куда
идти, — нужен обход в глубину с пометками вершин (см. тему 13).

## Почему быстрый обязательно догонит медленного

Это главный вопрос темы, и ответ на него стоит понимать до конца.

Пусть оба указателя уже внутри цикла длины `L`. Посмотрим на `gap` — сколько
шагов быстрому осталось пройти вперёд по кругу, чтобы оказаться на одном узле
с медленным. Это число от 0 до `L − 1`.

За один ход медленный убегает на 1, быстрый приближается на 2, то есть `gap`
уменьшается **ровно на единицу**:

```text
gap:   5 → 4 → 3 → 2 → 1 → 0   встреча
```

Число, которое каждый ход уменьшается ровно на 1, не может проскочить ноль.
Быстрый не «перепрыгнет» медленного: перепрыгнуть можно только с расстояния 1,
а с расстояния 1 следующий ход даёт как раз 0. Именно поэтому скорости берут
1 и 2: при разнице скоростей в единицу доказательство занимает одну строку.

**Почему сложность линейная.** Пусть в списке `n` узлов, из них `m` — «хвост»
до входа в цикл, `L` — сам цикл, `m + L = n`.

- Цикла нет: быстрый упирается в конец за `n / 2` ходов.
- Цикл есть: через `m` ходов медленный входит в цикл (быстрый уже там).
  В этот момент `gap ≤ L − 1`, дальше он убывает на 1 за ход — значит, встреча
  случится не позже чем через `L` ходов (ровно `L` — когда хвоста нет и оба
  стартуют с одного узла). Всего не больше `m + L = n` ходов.

Попутно получаем полезный факт: до встречи медленный не успевает пройти
по циклу больше одного круга.

## Четыре приёма

### 1. Cycle detection (обнаружение цикла)

```text
 хвост, m узлов          цикл, L узлов
 ┌────────────────────┐  ┌─────────────┐
 [a] → [b] → [c] → [d] → [e] → [f] → [g]
                          ↑           │
                          └───────────┘
```

Здесь голова — узел `[a]`, вход в цикл — `[e]`: на него ссылается последний узел `[g]`.

```python
slow = fast = head
while fast is not None and fast.next is not None:
    slow = slow.next
    fast = fast.next.next
    if slow is fast:          # сравниваем узлы, а не значения
        return True
return False                  # быстрый дошёл до конца — цикла нет
```

Две детали шаблона, на которых чаще всего спотыкаются: проверять нужно и `fast`,
и `fast.next`; сравнивать указатели — **после** шага, потому что до первого
шага они оба стоят на голове.

### 2. Cycle entry (поиск входа в цикл)

Вторая фаза того же алгоритма. После встречи один указатель возвращаем
в голову, второй оставляем на месте встречи и двигаем оба **по одному шагу**.
Они сойдутся ровно на первом узле цикла (доказательство — в разборе задачи).

```python
probe = head
while probe is not meeting:
    probe = probe.next
    meeting = meeting.next
return probe                  # первый узел цикла
```

### 3. Midpoint (середина за один проход)

Быстрый идёт вдвое быстрее, поэтому когда он прошёл весь список, медленный
прошёл половину. Длину считать не нужно.

```python
slow = fast = head
while fast is not None and fast.next is not None:
    slow = slow.next
    fast = fast.next.next
return slow                   # при чётной длине — второй из двух средних
```

Это стандартный кирпичик более крупных решений: проверка списка на палиндром,
сортировка слиянием для списка, «переплетение» списка — все начинаются
с поиска середины.

### 4. Implicit list (неявный список)

Узлов и ссылок может не быть вовсе. Если есть функция перехода `f`
и состояния рано или поздно начинают повторяться, то последовательность
`x, f(x), f(f(x)), …` — тот же список с хвостом и циклом, а `node.next`
заменяется вызовом `f`.

```python
slow = fast = start
while True:
    slow = f(slow)
    fast = f(f(fast))
    if slow == fast:          # здесь сравниваем уже значения: узел и есть значение
        break
```

Когда: счастливые числа, поиск повторяющегося числа в массиве без изменения
массива и без памяти (LeetCode 287), период псевдослучайного генератора.

### Есть ли в списке цикл

**Условие.** Дана голова односвязного списка. Вернуть `True`, если, двигаясь
по ссылкам `next`, мы никогда не дойдём до конца, — то есть какой-то узел
ссылается на один из предыдущих (или на себя).

**Наивное решение.** Складывать посещённые узлы в множество и проверять каждый
новый. Время O(n), но и память O(n). Важно: в множество кладут сами узлы
(их идентичность), а не значения — значения в списке могут повторяться.

**Идея.** Запускаем двух бегунов. Если дорога прямая, быстрый просто добежит
до конца. Если дорога замыкается в кольцо, быстрый зайдёт медленному в спину —
почему это неизбежно и почему займёт не больше `n` ходов, разобрано выше.

Пример: хвост из двух узлов и цикл из четырёх.

```text
 4 → 8 → 15 → 16 → 23 → 42
          ↑              │
          └──────────────┘        m = 2, L = 4

ход 1   slow = 8    fast = 15
ход 2   slow = 15   fast = 23     медленный вошёл в цикл, gap = 2
ход 3   slow = 16   fast = 15     gap = 1
ход 4   slow = 23   fast = 23     gap = 0 → цикл есть
```

Четыре хода при `n = 6` — в рамках оценки `m + L`.

### Где начинается цикл

Этой функции в списке задач главы нет, но это естественное продолжение
задачи, поэтому она добавлена в тот же файл — `linked_list_loop_start`.

**Условие.** Вернуть первый узел цикла (тот, на который ссылается «последний»
узел списка) или `None`, если цикла нет.

**Идея.** Находим точку встречи, как в предыдущей задаче. Затем ставим один
указатель в голову, другой оставляем в точке встречи и двигаем оба по одному
шагу. Узел, на котором они совпадут, — вход в цикл.

**Почему это работает.** Обозначим: `m` — шагов от головы до входа в цикл,
`L` — длина цикла, `k` — на сколько шагов точка встречи отстоит от входа
(считая по ходу движения).

```text
 head ── m шагов ──→ [вход] ── k шагов ──→ [встреча]
                        ↑                      │
                        └──── L − k шагов ─────┘
```

1. К моменту встречи медленный прошёл `m + k` шагов. (Он мог бы накрутить
   ещё и целые круги, но на рассуждение это не влияет.)
2. Быстрый прошёл ровно вдвое больше: `2(m + k)`.
3. Оба стоят на одном узле, значит, разница их путей — целое число кругов:
   `2(m + k) − (m + k) = m + k` делится на `L`.
4. Теперь возьмём указатель в точке встречи и сдвинем его на `m` шагов вперёд.
   Относительно входа он окажется на расстоянии `k + m` — а это целое число
   кругов, то есть **на самом входе**.
5. Указатель, стартующий из головы, через те же `m` шагов тоже стоит на входе.

Само `m` мы не знаем, но знать его и не нужно: идём синхронно и останавливаемся
при первом совпадении. Раньше входа совпасть нельзя — до `m`-го шага один
указатель ещё в хвосте, а другой уже в цикле.

Продолжение того же примера (`m = 2`, `k = 2`, `L = 4`, и `m + k = 4`
действительно делится на `L`):

```text
встреча была на узле 23

старт   from_head = 4    from_meeting = 23
шаг 1   from_head = 8    from_meeting = 42
шаг 2   from_head = 15   from_meeting = 15    → цикл начинается с узла 15
```

**Сложность.** Первая фаза — не больше `n` ходов, вторая — ровно `m ≤ n`.
Итого O(n) времени и O(1) памяти.

**Бонус.** Длину цикла получить ещё проще: от точки встречи пройти круг
одним указателем, считая шаги, пока не вернёмся в ту же точку.

### Середина списка

**Условие.** Вернуть средний узел односвязного списка. Если узлов чётное
число и средних два — вернуть **второй**. Для пустого списка — `None`.

**Наивное решение.** Первым проходом посчитать длину, вторым — дойти до
узла `n // 2`. Тоже O(n) и O(1), но два прохода; если список приходит потоком
и перемотать его нельзя, такой вариант не годится.

**Идея.** Когда быстрый указатель заканчивает путь, медленный прошёл ровно
половину его шагов. Нечётная и чётная длина различаются только тем, как
именно быстрый «финиширует»:

```text
нечётная длина: 3 → 1 → 4 → 1 → 5

ход 1   slow = 1   fast = 4
ход 2   slow = 4   fast = 5      у fast нет next → стоп, ответ 4

чётная длина: 2 → 7 → 1 → 8 → 2 → 9

ход 1   slow = 7   fast = 1
ход 2   slow = 1   fast = 2
ход 3   slow = 8   fast = None   fast вышел за край → стоп, ответ 8 (второй средний)
```

После `t` ходов медленный стоит на узле с индексом `t`, быстрый — на `2t`.
Цикл с условием `fast and fast.next` делает `n // 2` ходов, поэтому ответ —
узел с индексом `n // 2`: для нечётной длины это единственная середина,
для чётной — вторая из двух.

**Как получить первый из двух средних.** Нужно, чтобы при чётной длине не
выполнялся последний ход — тот, на котором быстрый сваливается в `None`.
Для этого условие цикла делают строже: быстрый обязан *приземлиться на узел*.

```python
slow = fast = head                       # head is not None
while fast.next is not None and fast.next.next is not None:
    slow = slow.next
    fast = fast.next.next
return slow                              # индекс (n - 1) // 2
```

На списке `2 → 7 → 1 → 8 → 2 → 9` цикл остановится после второго хода
(`fast = 2`, за ним только один узел), и ответом будет `1`. Для нечётной
длины оба варианта дают один и тот же узел. Поскольку здесь сразу читается
`fast.next`, пустой список нужно отсечь заранее. Другой распространённый
способ — оставить обычное условие, но стартовать с `fast = head.next`.

Первый средний нужен чаще, чем кажется: чтобы разрезать список пополам
(сортировка слиянием, палиндром), нужен **последний узел левой половины** —
именно у него обнуляют `next`.

В файле это функция `linked_list_midpoint_first`, она тоже покрыта тестами.

### Счастливое число

**Условие.** Берём положительное целое число и заменяем его суммой квадратов
его цифр; с результатом поступаем так же, и так далее. Если процесс приходит
к 1, число называется счастливым. Вернуть `True` для счастливого числа
и `False` — для числа, у которого процесс зацикливается, не дойдя до 1.

**Почему это задача про список.** Связного списка в условии нет, но у каждого
числа ровно один «следующий» — значит, цепочка чисел устроена как список,
где роль `next` играет функция `сумма квадратов цифр`. Единица переходит
сама в себя: `1 → 1`. Получается, цикл есть **всегда**, вопрос только — какой:
из одной единицы или какой-то другой.

**Почему процесс не убегает в бесконечность.** У числа из `d` цифр сумма
квадратов не больше `81·d`. Для четырёхзначных и более длинных чисел это
меньше самого числа (`81·4 = 324 < 1000`, и дальше разрыв только растёт),
так что большие числа обязаны уменьшаться. А для числа меньше 1000 следующее
не превышает `81·3 = 243`. Значит, цепочка быстро попадает в отрезок
`1…243` и остаётся в нём, а в конечном множестве повтор неизбежен.

**Идея.** Обнаружение цикла на неявном списке: `slow` применяет функцию один
раз за ход, `fast` — дважды. Встреча гарантирована; остаётся посмотреть,
**где** она произошла: на единице — число счастливое, иначе — нет.
Отдельная проверка `fast == 1` внутри цикла не нужна: попав в 1, быстрый
там и останется, и медленный придёт к нему сам.

```text
n = 23, цепочка: 23 → 13 → 10 → 1 → 1 → …

ход 1   slow = 13   fast = 10
ход 2   slow = 10   fast = 1
ход 3   slow = 1    fast = 1     встреча на 1 → True

n = 24, цепочка: 24 → 20 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → …
                      └───────── цикл из 8 чисел ─────────┘

ход 1   slow = 20    fast = 4
ход 2   slow = 4     fast = 37
ход 3   slow = 16    fast = 89
ход 4   slow = 37    fast = 42
ход 5   slow = 58    fast = 4
ход 6   slow = 89    fast = 37
ход 7   slow = 145   fast = 89
ход 8   slow = 42    fast = 42   встреча не на 1 → False
```

Любопытный факт: все несчастливые числа попадают в один и тот же цикл —
тот самый, что виден в примере (`4 → 16 → 37 → 58 → 89 → 145 → 42 → 20`).
Зашивать его в код не стоит: решение с двумя указателями от этого знания
не зависит и потому не требует веры на слово.

**Сложность.** Один шаг стоит столько, сколько цифр в числе, — O(log n).
Дорогой только первый шаг: после него число не больше `81 · (число цифр)`,
дальше оно стремительно сжимается до отрезка `1…243`, а там и длина хвоста,
и длина цикла ограничены константой. Итого O(log n) времени и O(1) памяти. Вариант
с множеством увиденных чисел тоже корректен, и это множество невелико,
но формально это лишняя память, от которой можно
избавиться.

## Типичные ошибки

- **Проверка только `fast is not None`.** Тогда `fast.next.next` падает
  с `AttributeError` на списке нечётной длины. Нужны обе проверки, и именно
  в таком порядке: `fast is not None and fast.next is not None`.
- **Сравнение до шага.** Оба указателя стартуют с головы, поэтому проверка
  `slow is fast` в начале итерации сразу «находит цикл» в любом списке.
  Сначала шаг, потом сравнение.
- **Сравнение значений вместо узлов.** `slow.val == fast.val` даст ложный
  цикл на списке `5 → 5 → 5`. В Python узлы сравнивают через `is`. В задаче
  про счастливые числа, наоборот, сравниваются значения — там число и есть узел.
- **Вторая фаза с разными скоростями.** При поиске входа в цикл оба указателя
  идут по одному шагу. Если по привычке оставить быстрому два шага,
  рассуждение про `m + k` перестаёт работать.
- **Забытый выход при отсутствии цикла.** Перед второй фазой нужно убедиться,
  что встреча вообще была; иначе — разыменование `None`.
- **Не тот средний узел.** Условие `fast and fast.next` даёт второй из двух
  средних, `fast.next and fast.next.next` — первый. Перед тем как писать код,
  уточните, какой нужен, и проверьте себя на списке из двух узлов.
- **Бесконечный цикл в «счастливом числе».** Условие `while n != 1` без
  обнаружения цикла не завершится, например, на числе 2.
- **`repr` узла, печатающий соседей.** На зацикленном списке отладочная
  печать уходит в бесконечную рекурсию — печатайте только значение.
