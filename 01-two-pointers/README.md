# 01. Two Pointers (два указателя)

## Суть в двух предложениях

Указатель — это просто индекс (или ссылка на узел списка). Два указателя,
которые двигаются **по правилу, а не перебором**, позволяют заменить вложенный
цикл O(n²) одним проходом O(n) и обойтись без дополнительной памяти.

Правило движения возможно только тогда, когда данные **предсказуемы**: сдвинув
указатель, мы заранее знаем, что изменится. В отсортированном массиве шаг вправо
не уменьшает значение. В палиндроме символы симметричны относительно центра.
Именно эта предсказуемость и даёт право отбрасывать варианты не проверяя их.

## Как узнать паттерн

Проверьте условие по списку — чем больше совпадений, тем вероятнее Two Pointers:

- данные **линейные**: массив, строка, связный список;
- вход **отсортирован** или его можно отсортировать без потери смысла;
- ищем **пару** (тройку) элементов или величину, которая считается по двум позициям;
- есть **симметрия**: сравниваем начало с концом;
- требуют изменить массив **на месте**, с памятью O(1);
- наивное решение — два вложенных цикла по одному и тому же массиву.

Контрпример: нужны *индексы* пары в **неотсортированном** массиве. Сортировка
перемешает индексы, поэтому здесь уместнее хеш-таблица (см. тему 02).

## Три стратегии

### 1. Inward traversal (встречное движение)

Указатели стартуют с краёв и идут навстречу, пока не встретятся.

```text
[ a  b  c  d  e  f ]
  ^              ^
  lo →        ← hi
```

```python
lo, hi = 0, len(data) - 1
while lo < hi:
    if нашли_ответ(data[lo], data[hi]):
        return ...
    if нужно_больше(data[lo], data[hi]):
        lo += 1
    else:
        hi -= 1
```

Когда: пара с суммой в отсортированном массиве, палиндромы, разворот на месте,
«контейнер с водой».

### 2. Unidirectional traversal (однонаправленное движение)

Оба указателя идут слева направо с разной ролью: `read` **разведывает**,
`write` **помнит границу** уже готовой части.

```text
[ 4  7  0  0  9  0 ]
        ^     ^
      write  read      слева от write — готовый результат
```

```python
write = 0
for read in range(len(data)):
    if подходит(data[read]):
        data[write], data[read] = data[read], data[write]
        write += 1
```

Когда: удалить/сдвинуть элементы на месте, убрать дубликаты из отсортированного
массива, разбить массив по условию.

### 3. Staged traversal (поэтапное движение)

Сначала работает только первый указатель — ищет особое место. Как только нашёл,
включается второй и добирает недостающую информацию относительно первого.

```python
first = найти_особую_позицию(data)
if first существует:
    second = найти_пару_для(data, first)
    обработать(data, first, second)
```

Когда: следующая перестановка, задачи вида «найди X, затем ближайший к нему Y».

### Пара с суммой в отсортированном массиве

**Условие.** Массив отсортирован по возрастанию. Вернуть индексы любых двух
элементов с суммой `target`, либо пустой список.

**Идея.** Берём самый маленький и самый большой элемент. Если сумма мала —
единственный способ её увеличить — сдвинуть `lo` вправо: сдвиг `hi` сумму только
уменьшит. Если велика — наоборот. Каждый шаг навсегда выбрасывает один элемент,
поэтому шагов не больше n.

**Почему ничего не теряем.** Пусть сумма мала и мы выбрасываем `nums[lo]`. Его
лучший возможный партнёр — `nums[hi]`, самый большой из оставшихся. Раз даже
с ним не хватило, с остальными не хватит тем более.

```text
nums = [-7, -1, 2, 5, 9], target = 4

lo=0 hi=4   -7 + 9 =  2  < 4   → lo += 1
lo=1 hi=4   -1 + 9 =  8  > 4   → hi -= 1
lo=1 hi=3   -1 + 5 =  4  ✓     → [1, 3]
```

### Тройки с нулевой суммой

**Условие.** Вернуть все тройки значений с суммой 0, без повторяющихся троек.

**Идея.** Сводим к предыдущей задаче: сортируем, фиксируем первый элемент `a`
и ищем в правой части пару с суммой `-a` встречными указателями. n итераций
по O(n) — итого O(n²), и это лучше перебора за O(n³).

**Главная сложность — дубликаты.** Хранить тройки в множестве необязательно,
в отсортированном массиве одинаковые значения стоят рядом:

- пропускаем `a`, если он равен предыдущему `a`;
- после найденной тройки пропускаем повторы второго элемента. Третий проверять
  не нужно: при фиксированных `a` и `b` он определён однозначно.

**Отсечение.** Если `a > 0`, дальше все числа положительные — выходим из цикла.

### Палиндром без учёта знаков и регистра

**Условие.** Учитываются только буквы и цифры, регистр не важен. Пустая строка
и строка из одних знаков — палиндромы.

**Идея.** Встречные указатели. Каждый перешагивает через «мусорные» символы,
значимые сравниваются в нижнем регистре.

**Почему не `cleaned == cleaned[::-1]`.** Это тоже O(n) по времени, но O(n)
по памяти. Если дополнительная память недопустима, выручают как раз
два указателя.

В решении намеренно **один** цикл с ветками вместо вложенных `while`: так
невозможно забыть проверку `lo < hi` при пропуске символов.

### Самый вместительный контейнер

**Условие.** `heights[i]` — высота вертикальной линии в точке `i`. Выбрать две
линии так, чтобы между ними поместилось максимум воды:
`min(h[i], h[j]) * (j - i)`.

**Идея.** Начинаем с максимальной ширины. Дальше ширина будет только падать,
значит выигрывать можно лишь высотой. Объём ограничивает **низкая** стенка:

- двигаем высокую → ширина меньше, высота не больше прежней → хуже или так же;
- двигаем низкую → есть шанс встретить стенку повыше.

Поэтому всегда двигаем низкую. При равных высотах можно двигать любую: пара
из двух равных стенок уже учтена, а любой другой контейнер с одной из них
будет у́же и не выше.

```text
heights = [3, 9, 4, 1, 8, 2]

lo=0 hi=5   min(3,2)*5 = 10           → двигаем hi (2 < 3)
lo=0 hi=4   min(3,8)*4 = 12           → двигаем lo
lo=1 hi=4   min(9,8)*3 = 24  ← ответ  → двигаем hi
lo=1 hi=3   min(9,1)*2 =  2           → двигаем hi
lo=1 hi=2   min(9,4)*1 =  4           → встретились
```

### Сдвинуть нули в конец

**Условие.** На месте перенести все нули в конец, порядок остальных сохранить.

**Идея.** `write` — граница «чистой» части, `read` бежит вперёд. Каждый
ненулевой элемент меняется местами с позицией `write`. Инвариант: между `write`
и `read` лежат только нули, поэтому обмен ничего не портит.

### Следующая перестановка

**Условие.** Вернуть следующую по алфавиту перестановку символов строки;
для самой последней — самую первую.

**Идея в три шага.**

1. Справа налево ищем *pivot* — первый символ, который меньше правого соседа.
   Всё, что правее, стоит по невозрастанию, то есть хвост уже «максимален»
   и увеличить строку, меняя только его, нельзя.
2. В хвосте ищем самый правый символ больше pivot и меняем их местами.
   Это минимально возможное увеличение в позиции pivot.
3. Разворачиваем хвост: он был невозрастающим, станет неубывающим — то есть
   минимальным продолжением.

```text
b d c a      хвост «d c a» не возрастает, pivot = 'b'
c d b a      поменяли 'b' с самым правым символом больше него — 'c'
c a b d      развернули хвост
```

Если pivot не нашёлся, строка — последняя перестановка; разворот всей строки
даёт первую.

## Типичные ошибки

- **`while lo <= hi` вместо `lo < hi`.** Для пар элемент нельзя брать дважды.
  Сравните с бинарным поиском, где `<=` как раз нужен.
- **Забытая сортировка.** Встречное движение по неотсортированному массиву
  выдаёт случайный результат и при этом не падает — ошибка тихая.
- **Сортировка, когда нужны исходные индексы.** Сортировка их теряет.
- **Дубликаты в задаче о тройках.** Пропуск повторов нужен и для первого
  элемента, и для второго; проверять надо с *предыдущим* значением
  (`values[i] == values[i - 1]`), иначе потеряется тройка вида `[-1, -1, 2]`.
- **Выход за границу при пропуске символов.** Вложенный `while` без условия
  `lo < hi` упадёт на строке из одних знаков препинания.
- **Сдвиг высокой стенки в «контейнере».** Работает на части тестов и потому
  коварен. Поэтому важно уметь доказать, почему двигать нужно именно низкую.
