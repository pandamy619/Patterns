# 19. Math and Geometry (математика и геометрия)

## Суть в двух предложениях

В этих задачах нет хитрой структуры данных: решает **наблюдение** — формула,
инвариант или удачное представление величины, после которого код занимает
десяток строк. Вся сложность уходит в аккуратность: границы, знаки, ноль,
переполнение и точность — здесь ошибаются чаще, чем в самом алгоритме.

Поэтому тема — это не один паттерн, а набор привычек: считать в целых числах,
проверять переполнение до операции, описывать область инвариантом и искать,
как задача размера n сводится к задаче размера n − 1.

## Как узнать паттерн

- в условии **координаты, точки, прямые, матрица как сетка** — геометрия;
- речь о **цифрах числа**, делимости, остатках, диапазоне типа («32-битное»);
- процесс **повторяется по кругу или по слоям**, и каждый шаг похож на предыдущий;
- «в лоб» задача симулируется, но просят быстрее или без дополнительной памяти —
  значит, у симуляции есть **формула**;
- сравнивать нужно **отношения** (наклоны, пропорции), а не сами числа.

Контрпример: «найти две ближайшие точки» или «k ближайших к началу координат».
Координаты есть, но математического трюка нет — это сортировка, куча
(тема 08) или «разделяй и властвуй». Геометрия во входных данных ещё не значит,
что задача из этой темы.

## Что нужно знать про числа в Python

| Факт | Следствие |
|---|---|
| `int` безразмерный | переполнения не бывает — его приходится **изображать** проверками |
| `//` округляет **вниз**, а не к нулю | `-47 // 10 == -5`, а не `-4` |
| `%` берёт знак **делителя** | `-47 % 10 == 3`, а не `-7` |
| `float` — 53 значащих бита | `0.1 + 0.2 != 0.3`; разные дроби могут дать одинаковый `float` |
| `math.gcd` неотрицателен, `gcd(0, a) == abs(a)` | вертикаль и горизонталь сокращаются без особых случаев |

В C++ и Java деление усекает к нулю, остаток берёт знак делимого. Если
вы переносите решение между Python и Java или C++, помните
об этой разнице — она ломает ровно те задачи, что в этой главе.

## Четыре приёма

### 1. Shrinking boundaries (сжимающиеся границы)

Непройденная часть матрицы — всегда прямоугольник. Его задают четыре числа:
`top`, `bottom`, `left`, `right`. Прошли сторону — сдвинули соответствующую
границу внутрь. Матрица посещённых клеток не нужна: всё, что снаружи
прямоугольника, уже обработано.

```text
        left          right
          ↓             ↓
top →     ┌─ → → → → → ─┐
          ↑             ↓
          ↑             ↓
bottom →  └─ ← ← ← ← ← ─┘
```

```python
top, bottom = 0, rows - 1
left, right = 0, cols - 1
while top <= bottom and left <= right:
    пройти_верх(top, left..right);      top += 1
    пройти_право(right, top..bottom);   right -= 1
    if top <= bottom:                   # прямоугольник мог схлопнуться
        пройти_низ(bottom, right..left); bottom -= 1
    if left <= right:
        пройти_лево(left, bottom..top);  left += 1
```

Когда: спираль, заполнение матрицы по спирали, обход по слоям, поворот матрицы.

### 2. Overflow guard (проверка переполнения заранее)

Проверять `result > MAX` **после** умножения бессмысленно: в языке
с фиксированной разрядностью переполнение уже случилось. Неравенство
переносят на безопасную сторону — делят границу, а не умножают значение:

```text
value * 10 + digit > MAX
        ⇕
value > MAX // 10   или   (value == MAX // 10  и  digit > MAX % 10)
```

```python
if value > MAX // 10 or (value == MAX // 10 and digit > MAX % 10):
    return 0            # следующего шага число не переживёт
value = value * 10 + digit
```

Для сложения то же самое: `a + b > MAX` ⇔ `a > MAX - b` (при `b ≥ 0`).
Отсюда и классическое `mid = lo + (hi - lo) // 2` в бинарном поиске.

Когда: разбор числа по цифрам, `atoi`, накопление произведений и сумм
в заданном диапазоне.

### 3. Exact slope (точный наклон: дробь вместо float)

Наклон `dy / dx` — рациональное число. Храним его как пару целых, приведённую
к каноническому виду, и кладём в хеш-таблицу как ключ:

```python
g = gcd(dy, dx)                 # 1. сократить: (2, 4) и (3, 6) → (1, 2)
dy, dx = dy // g, dx // g
if dx < 0 or (dx == 0 and dy < 0):
    dy, dx = -dy, -dx           # 2. знак: (1, 2) и (-1, -2) — одна прямая
```

Оба шага обязательны: без сокращения не совпадут одинаковые наклоны
с разным «масштабом», без нормализации знака — точки по разные стороны
от опорной. Вертикальная прямая получается сама собой: `gcd(dy, 0) == |dy|`,
ключ `(1, 0)`, деления на ноль нет.

Если нужно только **сравнить** два наклона, дробь можно вообще не строить:
`dy1 / dx1 == dy2 / dx2` ⇔ `dy1 * dx2 == dy2 * dx1`. Это векторное
произведение, и оно тоже целочисленное.

Когда: коллинеарность, параллельность, группировка по направлению, любые
сравнения пропорций.

### 4. Recurrence (рекуррентное соотношение)

Сделали один шаг процесса — и увидели **ту же задачу меньшего размера**,
только с переименованными элементами. Остаётся выписать, как ответ меньшей
задачи переводится обратно в исходную нумерацию.

```python
answer = ответ_для_размера_1
for size in range(2, n + 1):
    answer = перевести(answer, size)     # O(1) на шаг
```

Формула пишется сверху вниз (рекурсия), а вычисляется снизу вверх (цикл):
так пропадает стек глубиной n.

Когда: задача Иосифа, подсчёты по слоям, «что останется после n раундов».

### Обход матрицы по спирали

**Условие.** Дана матрица m × n. Вернуть её элементы в порядке спирали
по часовой стрелке, начиная с левого верхнего угла.

**Идея.** Четыре границы и четыре прохода на виток: верх слева направо, правая
сторона сверху вниз, низ справа налево, левая сторона снизу вверх. После
каждого прохода граница сдвигается, поэтому углы не дублируются: верхний проход
забирает оба верхних угла, а правый стартует уже с обновлённого `top`.

**Где ошибаются.** Условие цикла проверяется один раз на виток, а границы
внутри витка меняются дважды до того, как мы пойдём обратно. Если осталась одна
строка, верхний проход её заберёт, `top` перешагнёт `bottom`, и нижний проход
без проверки `top <= bottom` выдаст ту же строку задом наперёд. Симметрично —
для одного столбца и проверки `left <= right`.

**Сложность.** Каждая клетка попадает в ответ ровно один раз — O(mn).
Дополнительная память — четыре числа.

```text
matrix = 11 12 13 14
         21 22 23 24
         31 32 33 34

виток 1   top=0 bottom=2 left=0 right=3
  вправо  11 12 13 14        top=1
  вниз    24 34              right=2
  влево   33 32 31           bottom=1
  вверх   21                 left=1

виток 2   top=1 bottom=1 left=1 right=2
  вправо  22 23              top=2
  вниз    —                  right=1
  влево   пропуск: top=2 > bottom=1   (иначе 22 попало бы в ответ дважды)
  вверх   —                  left=2

ответ: 11 12 13 14 24 34 33 32 31 21 22 23
```

### Развернуть 32-битное число

**Условие.** Дано целое `n` из диапазона [−2³¹, 2³¹ − 1]. Вернуть число
с теми же цифрами в обратном порядке, знак сохранить. Если результат
не помещается в тот же диапазон — вернуть 0. Хранить значения шире 32 бит
нельзя — даже промежуточные.

**Идея.** Отрываем последнюю цифру от `n` и приписываем её справа
к результату: `result = result * 10 + digit`. Перед этим шагом проверяем,
переживёт ли его `result` (приём 2). Границы без последней цифры —
214 748 364 и −214 748 364, последние цифры — 7 и −8.

**Знак.** Соблазнительно взять `abs(n)`, развернуть и вернуть знак. Но
`abs(−2³¹) = 2³¹` в 32 бита не влезает — отрицательных чисел на одно больше.
Поэтому знак не отделяем вовсе: у отрицательного числа отрываем
**отрицательные** цифры, и результат сам растёт в минус.

**Особенность Python.** Нужно деление с усечением к нулю, а `//` и `%`
работают иначе: `-47 % 10 == 3`, `-47 // 10 == -5`. В решении цифра
исправляется вручную (`3 − 10 = −7`), а затем `(n − digit) // 10` делится уже
нацело и ни в какую сторону не округляется. По той же причине граница записана
числом: `INT_MIN // 10` в Python равно −214 748 365, а не −214 748 364.

**Любопытная деталь.** Вторая половина проверки (`digit > 7`) на корректном
входе не срабатывает никогда: десятая цифра результата — это первая цифра `n`,
а у десятизначного 32-битного числа она не больше 2. Убирать проверку всё же
не стоит — она делает условие верным само по себе, без рассуждений о входе.

```text
n = -9051
  цифра -1   n = -905   result =     0 → -1
  цифра -5   n =  -90   result =    -1 → -15
  цифра  0   n =   -9   result =   -15 → -150
  цифра -9   n =    0   result =  -150 → -1509
ответ: -1509

n = 1563847412            (развёрнутое 2147483651 > 2147483647)
  ...девять шагов без происшествий...   result = 214748365, осталась цифра 1
  214748365 > 214748364 → умножать нельзя → ответ 0
```

### Максимум точек на одной прямой

**Условие.** Даны n **различных** точек с целыми координатами. Найти
наибольшее число точек, лежащих на одной прямой.

**Идея.** Фиксируем опорную точку. Любая прямая через неё задаётся одним
наклоном, поэтому остальные точки достаточно сгруппировать по наклону
в хеш-таблице: самая большая группа плюс сама опорная — лучший ответ для этой
точки. Повторяем для каждой опорной, таблицу каждый раз заводим заново.

**Почему таблицу нельзя сделать общей.** Один наклон — это целое семейство
параллельных прямых. Наклон определяет прямую, только пока закреплена точка,
через которую она проходит.

**Почему не float.** Наклон — ключ таблицы, сравнение идёт на точное равенство.
У `float` 53 значащих бита, и разные дроби в них склеиваются:

```text
1000000000 / 999999999  →  1.000000001
1000000001 / 1000000000 →  1.000000001     (в float — один и тот же набор бит)
```

Точки (0, 0), (999999999, 1000000000) и (1000000000, 1000000001) на одной
прямой не лежат, а решение на `float` насчитает три. Этот случай есть в тестах.
Пара целых `(dy, dx)` после сокращения и нормализации знака (приём 3) —
ключ точный, и вертикальная прямая для него не особый случай.

**Отсечение.** Для опорной с индексом `i` смотрим только точки правее.
Лучшую прямую целиком увидит та её точка, у которой индекс наименьший.
Асимптотика та же, O(n²), но работы вдвое меньше.

**Если бы точки могли повторяться,** совпадающие с опорной пришлось бы считать
отдельно (наклон для них не определён, `gcd(0, 0) == 0`) и прибавлять
к каждой группе. В нашем условии этого случая нет.

```text
points = (0,1) (2,2) (4,3) (1,4) (6,4) (4,0)

опорная (0,1):
  (2,2)  dy=1  dx=2             → (1, 2)
  (4,3)  dy=2  dx=4   gcd=2     → (1, 2)
  (1,4)  dy=3  dx=1             → (3, 1)
  (6,4)  dy=3  dx=6   gcd=3     → (1, 2)
  (4,0)  dy=-1 dx=4             → (-1, 4)
  наклон (1, 2) встретился 3 раза → 3 + 1 = 4 точки

опорная (2,2):
  (1,4)  dy=2  dx=-1  знак      → (-2, 1)
  ...лучшая группа — снова (1, 2): 2 + 1 = 3

опорная (4,3):
  (4,0)  dy=-3 dx=0   gcd=3, знак → (1, 0)   вертикаль
  ...

ответ: 4   (прямая y = x/2 + 1)
```

### Задача Иосифа Флавия

**Условие.** n человек с номерами 0…n−1 стоят по кругу. Отсчёт начинается
с нулевого; каждый k-й выбывает, счёт продолжается со следующего за ним.
Вернуть номер того, кто останется последним. (На LeetCode нумерация
с единицы — там к ответу нужно прибавить 1.)

**Наивно.** Симулировать круг списком: n − 1 удаление по O(n) — итого O(n²).
Именно такая симуляция служит эталоном в тестах.

**Идея.** Пусть `J(n)` — ответ для круга из n человек. Первым выбывает номер
`(k − 1) % n`, новый отсчёт начинается с номера `k % n`. Осталась **та же
задача** для n − 1 человека, только номера сдвинуты: тот, кого новая задача
считает нулевым, в старой нумерации был `k % n`, первый — `(k + 1) % n`
и так далее. Значит, если в малой задаче выжил номер `s`, в исходной это
`(s + k) % n`:

```text
J(1) = 0
J(n) = (J(n − 1) + k) % n
```

Рекурсия по этой формуле занимает O(n) стека и при n порядка тысячи упирается
в лимит Python. Цикл от 2 до n считает то же самое с памятью O(1).

```text
n = 6, k = 4

симуляция:  0 1 2 [3] 4 5  →  0 [1] 2 4 5  →  [0] 2 4 5  →  [2] 4 5  →  4 [5]  →  4

формула:    J(1) = 0
            J(2) = (0 + 4) % 2 = 0
            J(3) = (0 + 4) % 3 = 1
            J(4) = (1 + 4) % 4 = 1
            J(5) = (1 + 4) % 5 = 0
            J(6) = (0 + 4) % 6 = 4    ← ответ
```

Для k = 2 есть и замкнутая формула: если n = 2ᵐ + r, где r < 2ᵐ, выживает
номер 2r. В тестах она проверяет итеративный вариант на большом n.

### Сколько троек образуют треугольник

**Условие.** Дан массив неотрицательных длин. Сколько троек элементов
(тройки различаются индексами) могут быть сторонами **невырожденного**
треугольника? См. сноску под таблицей: постановка в книге может отличаться.

**Математика.** Треугольник существует, когда каждая сторона меньше суммы двух
других, — это три неравенства. Но если стороны упорядочены, `a ≤ b ≤ c`, два
из них выполняются автоматически, и остаётся одно: `a + b > c`. Строгое:
при равенстве треугольник сплющивается в отрезок.

**Идея.** Сортируем. Перебираем наибольшую сторону `c` справа налево, а пару
`(a, b)` ищем слева от неё встречными указателями (стратегия inward из темы 01):

- `sides[lo] + sides[hi] > c` — тогда с этим `hi` подойдёт и любой индекс
  между `lo` и `hi`, ведь там числа не меньше. Засчитываем сразу `hi − lo` пар
  и сдвигаем `hi`;
- иначе `sides[lo]` слишком мал даже для самого большого партнёра — сдвигаем `lo`.

Нули отдельной проверки не требуют: `0 + b > c` при `b ≤ c` невозможно.

**Сложность.** Для каждого `c` указатели вместе делают не больше n шагов:
O(n²) против O(n³) у перебора троек. Вариант с бинарным поиском второй
границы даёт O(n² log n) — два указателя лучше.

```text
lengths = [7, 3, 5, 10, 4]  →  sides = [3, 4, 5, 7, 10]

c = 10   lo=0 hi=3   3 + 7 = 10  не больше      → lo += 1
         lo=1 hi=3   4 + 7 = 11  > 10   +2      → hi -= 1     (4,7,10) (5,7,10)
         lo=1 hi=2   4 + 5 =  9  не больше      → lo += 1
c = 7    lo=0 hi=2   3 + 5 =  8  > 7    +2      → hi -= 1     (3,5,7) (4,5,7)
         lo=0 hi=1   3 + 4 =  7  не больше      → lo += 1
c = 5    lo=0 hi=1   3 + 4 =  7  > 5    +1      → hi -= 1     (3,4,5)

ответ: 5
```

## Типичные ошибки

- **Спираль без проверок внутри витка.** Неквадратные матрицы с нечётной
  меньшей стороной (1 × n, n × 1, 3 × 4, 5 × 3…) дублируют элементы: в центре
  остаётся полоска, и её проходят дважды. Квадратные матрицы при этом работают
  верно — на них ошибка не видна.
- **Проверка переполнения после операции.** `if result > INT_MAX` в Python
  работает, в Java — нет: число уже «перевернулось». Если условие говорит
  про 32 бита, проверяйте до умножения.
- **`abs(INT_MIN)`.** В дополнительном коде у самого маленького числа нет
  положительной пары.
- **`//` и `%` для отрицательных чисел в Python.** `-47 // 10 == -5`. Либо
  исправляйте остаток вручную, либо пользуйтесь `math.fmod` и `int(a / b)` —
  но последнее снова приводит к `float` и потере точности на больших числах.
- **Наклон как `float`** — или, что то же самое, как `round(dy / dx, 9)`.
  Округление не лечит проблему, а добавляет ложные совпадения.
- **Сокращение без нормализации знака.** `(1, 2)` и `(−1, −2)` станут разными
  ключами, и прямая, проходящая *через* опорную точку, распадётся на два луча.
- **Общая таблица наклонов на все опорные точки.** Параллельные прямые
  сольются в одну.
- **Сдвиг в задаче Иосифа.** `(J + k) % n`, а не `(J + k − 1) % n` — при
  нумерации с нуля. При нумерации с единицы проще посчитать с нуля и прибавить 1
  в самом конце, чем тащить ±1 через формулу.
- **Нестрогое неравенство треугольника.** `a + b >= c` засчитает вырожденные
  тройки вроде 1, 2, 3.
