# 08. Heaps (кучи)

## Суть в двух предложениях

Куча — это структура, которая в любой момент за O(1) показывает **самый
приоритетный** элемент (минимум или максимум), а добавление и извлечение
обходятся в O(log n). Она нужна там, где полная сортировка избыточна: данные
приходят порциями или нас интересует только «верхушка» — лучший элемент,
k лучших, середина.

Куча наводит порядок ровно настолько, насколько нужно для ответа на вопрос
«кто следующий?», и не тратит время на всё остальное.

## Как узнать паттерн

- в условии звучит **«k самых …»**: больших, частых, близких, дешёвых;
- нужен **минимум или максимум много раз подряд**, а набор между запросами
  меняется — элементы добавляются и уходят;
- данные приходят **потоком**, и отвечать надо после каждого элемента;
- есть **несколько отсортированных источников**, которые надо слить или
  просматривать «в порядке возрастания по всем сразу»;
- нужна **медиана** или другая порядковая статистика по пополняемому набору;
- наивное решение — «отсортировать всё заново после каждого изменения» или
  «линейно искать минимум на каждом шаге».

Контрпример: набор фиксирован и нужен один ответ — например, k-й по величине
элемент готового массива без каких-либо обновлений. Куча сработает, но проще
один раз отсортировать, а быстрее всего quickselect за O(n) в среднем (тема 17).
И второй: нужен поиск **произвольного** элемента или его удаление из середины —
куча умеет быстро работать только с вершиной, всё остальное в ней O(n).

## Что нужно знать про кучу

**Устройство.** Двоичная куча — это полное двоичное дерево (все уровни заполнены,
последний — слева направо), в котором выполняется **свойство кучи**: каждый
родитель не больше своих детей (min-куча) либо не меньше (max-куча). Между
братьями и между разными поддеревьями порядка нет — поэтому куча и дешевле
отсортированного массива.

Раз дерево полное, указатели не нужны — оно хранится в обычном массиве:

```text
индексы:    0   1   2   3   4   5
массив:   [ 2,  5,  3,  9,  6,  8 ]

              2              родитель i  → (i - 1) // 2
            /   \            дети i      → 2i + 1 и 2i + 2
           5     3
          / \   /            минимум всегда в ячейке 0,
         9   6 8             но массив НЕ отсортирован: 5 стоит раньше 3
```

**Сложность операций.**

| Операция | Время | Как работает |
|---|---|---|
| посмотреть вершину | O(1) | `heap[0]` |
| вставка | O(log n) | дописать в конец и поднимать, пока родитель «хуже» (sift up) |
| извлечь вершину | O(log n) | последний элемент поставить в корень и опускать (sift down) |
| построить из n элементов (heapify) | O(n) | sift down для всех узлов, начиная с нижних |
| найти / удалить произвольный элемент | O(n) | порядка между ветвями нет — только перебор |

Высота полного дерева — log n, отсюда логарифм у вставки и извлечения.

**Почему heapify — это O(n), а не O(n log n).** Узлы опускаются вниз, и путь
у каждого не длиннее высоты его поддерева. Половина узлов — листья, им
двигаться некуда. Четверть может опуститься на один уровень, восьмая — на два,
и так далее; длинный путь есть только у горстки узлов возле корня. Сумма
n/4 · 1 + n/8 · 2 + n/16 · 3 + … сходится к n. А вот n вставок по одной —
это честные O(n log n): там элементы *поднимаются*, и длинный путь достаётся
как раз многочисленным листьям.

**Особенности `heapq` в Python.**

- Это не класс, а набор функций над обычным `list`: `heappush`, `heappop`,
  `heapify`, `heappushpop`, `heapreplace`. Вершина — `heap[0]`.
- **Только min-куча.** Max-куча для чисел делается отрицанием: кладём `-x`,
  при чтении снова меняем знак.
- Составной приоритет — **кортеж**: кортежи сравниваются поэлементно слева
  направо. `(-частота, строка)` — «сначала частые, при равенстве — по алфавиту».
- Сравнение кортежей при равенстве первых полей идёт дальше. Если в конце
  лежит объект без оператора `<` (узел списка, словарь), получится `TypeError` —
  причём только на тех данных, где случилась ничья. Лекарство — **tie-breaker**:
  уникальное число (номер источника, счётчик вставок) перед объектом.
- Строку отрицанием не перевернуть. Если нужен обратный порядок по нечисловому
  полю — маленький класс-обёртка со своим `__lt__`.
- `heapq.nlargest(k, data)` и `nsmallest` удобны в работе, но здесь
  мы разбираем механику вручную.

## Три приёма

### 1. Top-k (k лучших элементов)

Два способа, и выбор между ними — любимый дополнительный вопрос.

**Max-куча из всего.** Сложить все n элементов, `heapify`, извлечь k раз:
O(n + k log n) времени, O(n) памяти.

```python
heap = [(-приоритет(x), x) for x in data]
heapq.heapify(heap)
best = [heapq.heappop(heap)[1] for _ in range(k)]
```

**Min-куча размера k.** Держим только k текущих кандидатов. На вершине —
**худший** из них: новый элемент сравнивается именно с ним, и проигравший
уходит. O(n log k) времени, O(k) памяти.

```python
heap = []
for x in data:
    heapq.heappush(heap, (приоритет(x), x))
    if len(heap) > k:
        heapq.heappop(heap)          # выбросили худшего из k + 1
```

```text
ищем k больших  →  min-куча размера k  (на вершине — кандидат на вылет)
ищем k меньших  →  max-куча размера k
```

Кажется, что наоборот, — в этом и ловушка. Вариант с кучей размера k
незаменим для потока: данные целиком в память не помещаются, а k кандидатов —
вполне.

### 2. K-way merge (слияние k источников)

Общий минимум по всем отсортированным источникам — это всегда чья-то
**голова**. Поэтому в куче достаточно держать по одному элементу от источника.

```text
A: 2 → 5            куча: [ (1,B) (2,A) (5,C) ]
B: 1 → 5 → 8                  │
C: 5                          └─ извлекли 1 из B → на его место следующий узел B
```

```python
heap = [(src[0], i, 0) for i, src in enumerate(sources) if src]
heapq.heapify(heap)
while heap:
    value, i, pos = heapq.heappop(heap)
    выдать(value)
    if pos + 1 < len(sources[i]):
        heapq.heappush(heap, (sources[i][pos + 1], i, pos + 1))
```

В куче не больше k элементов, каждый из N элементов проходит через неё один
раз: O(N log k). Номер источника `i` заодно работает как tie-breaker.

Когда: слияние списков и файлов, «k-й элемент в отсортированной матрице»,
«k пар с наименьшей суммой», «наименьший диапазон, покрывающий все списки».

### 3. Two heaps (две кучи)

Делим набор на «меньшую» и «большую» половины. Меньшую держим в max-куче,
большую — в min-куче. Тогда обе границы раздела лежат на вершинах.

```text
          lower (max-куча)        upper (min-куча)
        [ -1   2   4 ]          [ 4   7   10 ]
                   ▲              ▲
                вершина        вершина
                   └── медиана ───┘
```

```python
# два инварианта после каждой вставки:
#   1) max(lower) <= min(upper)
#   2) len(lower) == len(upper)  или  len(lower) == len(upper) + 1
```

Когда: медиана потока, медиана в скользящем окне, задачи с «границей» между
двумя группами, которая сдвигается при каждом обновлении.

### K самых частых строк

**Условие.** Дан массив строк и число `k`. Вернуть `k` строк, которые
встречаются чаще всего, в порядке убывания частоты. При равной частоте раньше
идёт лексикографически меньшая строка. Гарантируется, что `k` не больше длины
массива; если уникальных строк всё же меньше `k`, решение возвращает все.

**Идея.** Задача распадается на две: посчитать частоты (`Counter`, тема 02)
и выбрать k лучших по составному ключу «частота ↓, строка ↑». Сортировка
всех уникальных строк — O(n log n). Куча позволяет не упорядочивать то, что
в ответ не попадёт.

**Вариант 1 — max-куча.** Кладём кортежи `(-частота, строка)`, делаем
`heapify` за O(n) и извлекаем k раз. Минус стоит **только у частоты**: при
ничьей кортежи сравниваются по строке, и меньшая по алфавиту выходит первой —
это ровно требуемый порядок.

```text
strs = ["tea", "milk", "tea", "jam", "milk", "tea", "rye", "jam"], k = 2
частоты: tea 3, milk 2, jam 2, rye 1

куча после heapify: [(-3,'tea'), (-2,'milk'), (-2,'jam'), (-1,'rye')]
pop → (-3, 'tea')
pop → (-2, 'jam')      milk и jam по 2, но 'jam' < 'milk'
ответ: ['tea', 'jam']
```

**Вариант 2 — min-куча размера k.** В куче только k кандидатов, на вершине —
худший. Здесь порядок сравнения **зеркальный**: хуже тот, у кого частота
меньше, а при равной частоте — кто *дальше* по алфавиту. Число перевернуть
легко, а «минус строки» не существует, поэтому в решении заведён маленький
класс `_Candidate` с собственным `__lt__`.

```text
пришло        куча (от худшего к лучшему)     выброшен
(tea, 3)      [tea:3]                         —
(milk, 2)     [milk:2, tea:3]                 —
(jam, 2)      [jam:2, tea:3]                  milk:2   ← ничья по частоте, milk дальше по алфавиту
(rye, 1)      [jam:2, tea:3]                  rye:1    ← вошёл и сразу вышел

извлекаем всё: jam, tea → разворачиваем → ['tea', 'jam']
```

Куча отдаёт кандидатов от худшего к лучшему, так что в конце ответ надо
развернуть — про это легко забыть.

**Что выбрать.** Если k близко к числу уникальных строк, выигрыша у второго
варианта почти нет, а кода больше. Если k мало, а уникальных строк миллионы
(или они приходят потоком), куча размера k экономит и время, и память.
Начинать разумно с первого варианта, а второй держать в уме как оптимизацию.

### Слияние k отсортированных списков

**Условие.** Дан массив из `k` голов односвязных списков, каждый отсортирован
по возрастанию. Собрать из них один отсортированный список и вернуть его
голову. Среди списков могут быть пустые, сам массив тоже может быть пуст.

**Идея.** Слияние двух списков — два указателя и одно сравнение на шаг. Для
k списков то же самое потребовало бы k сравнений на шаг, всего O(N·k). Но
искать минимум среди k голов — работа для кучи: извлекли наименьшую голову,
прицепили к ответу, положили в кучу следующий узел **из того же списка**.

**Почему достаточно одного узла от списка.** Внутри списка узлы упорядочены,
поэтому пока голова не извлечена, всё, что за ней, минимумом быть не может.

**Tie-breaker.** Напрашивается кортеж `(node.val, node)`. Он работает ровно
до первой ничьей: при равных значениях Python сравнивает вторые элементы, то
есть сами узлы, и падает с `TypeError: '<' not supported`. На тестах без
дубликатов ошибка не видна. Решение — вставить между значением и узлом номер
списка: `(node.val, index, node)`. От каждого списка в куче не больше одного
узла, значит номера не повторяются, и до сравнения узлов дело не доходит.

```text
A (0): 2 → 5        B (1): 1 → 5 → 8        C (2): 5
в куче пары (значение, номер списка)

куча                     извлекли   добавили   результат
[(1,1) (2,0) (5,2)]      (1,1)      (5,1)      1
[(2,0) (5,1) (5,2)]      (2,0)      (5,0)      1 2
[(5,0) (5,1) (5,2)]      (5,0)      —          1 2 5      ← три пятёрки: решает номер списка
[(5,1) (5,2)]            (5,1)      (8,1)      1 2 5 5
[(5,2) (8,1)]            (5,2)      —          1 2 5 5 5
[(8,1)]                  (8,1)      —          1 2 5 5 5 8
```

**Сложность.** Куча не вырастает больше k, каждый из N узлов один раз входит
и один раз выходит: O(N log k) времени, O(k) памяти. Новые узлы не создаются —
перевешиваются ссылки `next` у существующих.

**Альтернатива без кучи** — сливать списки попарно, как в merge sort:
log k раундов по O(N), те же O(N log k) и O(1) дополнительной памяти
в итеративном варианте. Полезно упомянуть, если спросят «а можно иначе?».

### Медиана потока чисел

**Условие.** Спроектировать структуру с двумя методами: `add(num)` принимает
очередное целое число, `get_median()` возвращает медиану всех принятых чисел
как `float`. Для чётного количества медиана — среднее двух центральных.
Считается, что до первого `get_median()` хотя бы одно число добавлено
(решение на пустом потоке бросает `ValueError`).

**Наивно.** Хранить отсортированный список и вставлять бинарным поиском:
место находится за O(log n), но сдвиг элементов — O(n) на каждую вставку.

**Идея.** Для медианы не нужен порядок *внутри* половин — важны только
элементы на границе: наибольший из меньшей половины и наименьший из большей.
«Наибольший из набора» — это вершина max-кучи, «наименьший» — вершина
min-кучи. Отсюда две кучи: `lower` (max-куча, числа хранятся с минусом)
и `upper` (min-куча).

После каждой вставки восстанавливаем два инварианта:

1. **Порядок:** любое число из `lower` не больше любого из `upper`.
   Новое число идёт в `lower`, если оно не больше её вершины, иначе в `upper`.
2. **Баланс:** размеры равны, либо в `lower` на один элемент больше.
   Если нарушился — перебрасываем одну вершину в соседнюю кучу. Порядок от
   этого не страдает: вершина `lower` — максимум своей половины, и он всё
   равно не больше всех чисел в `upper` (и симметрично).

Тогда медиана — вершина `lower` при нечётном количестве и среднее двух
вершин при чётном.

```text
add    lower (max-куча)   upper (min-куча)   медиана
  7    [7]                []                 7.0
  2    [2]                [7]                4.5     2 пошло в lower, стало 2:0 → 7 перебросили в upper
 10    [2, 7]             [10]               7.0     10 → upper, стало 1:2 → 7 вернули в lower
  4    [2, 4]             [7, 10]            5.5     4 → lower, стало 3:1 → 7 перебросили в upper
  4    [2, 4, 4]          [7, 10]            4.0     4 → lower, баланс 3:2 в порядке
 -1    [-1, 2, 4]         [4, 7, 10]         4.0     -1 → lower, стало 4:2 → 4 перебросили в upper
```

(Содержимое куч показано отсортированным для наглядности; в памяти порядок другой.)

**Сложность.** `add` — не больше трёх операций с кучей, O(log n).
`get_median` только смотрит на вершины — O(1). Память O(n): выбросить нельзя
ничего, любое старое число ещё может стать медианой.

**Дополнительный вопрос — скользящее окно.** Если числа ещё и *уходят*,
понадобится удаление из середины кучи, которого `heapq` не умеет. Стандартный
ответ — «ленивое удаление»: помечать ушедшие числа в таблице и выбрасывать
их, когда они всплывут на вершину.

## Типичные ошибки

- **Перепутать тип кучи в top-k.** Для k *наибольших* нужна *min*-куча размера
  k: выбрасывать надо худшего из кандидатов, значит, он и должен быть на вершине.
- **Кортеж без tie-breaker'а.** `(value, node)` падает с `TypeError` только
  при равных `value` — на простых примерах всё зелёное, на дубликатах авария.
- **Отрицание «за компанию».** В `(-count, word)` минус нужен только частоте.
  А для обратного порядка строк отрицания нет вообще — нужен `__lt__`.
- **Забыть вернуть знак.** Положили `-x` — при чтении тоже `-heap[0]`.
  Особенно легко ошибиться при переброске между кучами:
  `heappush(upper, -heappop(lower))`.
- **Считать кучу отсортированным массивом.** `heap[1]` — не второй по
  величине элемент, а `for x in heap` не даёт порядка. Упорядоченный вывод —
  только через последовательные `heappop`.
- **n вставок вместо `heapify`.** Когда все данные известны заранее, это
  O(n log n) против O(n). Мелочь, но показательная.
- **Не развернуть ответ** после min-кучи размера k: она отдаёт от худшего к лучшему.
- **Баланс без порядка в двух кучах.** Класть новое число «в ту кучу, что
  меньше» нельзя: сначала выбор по значению, потом выравнивание размеров.
- **Целочисленное деление в медиане.** `(a + b) // 2` для 3 и 6 даст 4, а не 4.5.
- **`heap.pop()` и `heap.sort()` по привычке.** `pop()` снимает *последний*
  элемент массива, а не вершину. Модуль `heapq` работает только через свои функции.
- **Назвать свой файл `heapq.py`.** Он заслонит стандартный модуль, и
  `import heapq` начнёт импортировать ваш же файл.
