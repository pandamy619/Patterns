# 14. Backtracking (перебор с возвратом)

## Суть в двух предложениях

Backtracking — это обход в глубину по **дереву решений**: ответ строится по
одному выбору за раз, а когда ветка закончилась (успехом или тупиком), последний
выбор отменяется и пробуется следующий вариант. От «тупого» полного перебора он
отличается тем, что тупиковую ветку можно бросить **сразу**, не достраивая её
до конца, — и тем, что на весь перебор хватает одного изменяемого состояния.

Быстрым backtracking не бывает: если нужно выдать все n! перестановок, меньше
n! шагов не получится. Задача паттерна — не потратить больше, чем требует сам
размер ответа, и не заходить туда, где ответа заведомо нет.

## Как узнать паттерн

- просят **все** варианты: «перечислите все…», «верните каждую комбинацию…»,
  либо **число** вариантов, для которого нет формулы;
- ответ — это **последовательность выборов** (какой элемент поставить следующим,
  брать или не брать, в какой столбец ставить ферзя);
- есть **ограничения**, которые можно проверить на недостроенном ответе
  (сумма уже превышена, клетка под боем);
- вход **маленький**: n ≤ 10–20, строка из нескольких цифр, доска 8×8 —
  так составители намекают на экспоненциальное решение;
- головоломки на расстановку: судоку, ферзи, раскраски, поиск слова в сетке.

Контрпример: нужны не сами комбинации, а только их **количество** или лучшее
значение, и при этом подзадачи повторяются — «сколькими способами набрать
сумму монетами». Перебор будет заново обходить одинаковые поддеревья; это задача
на динамическое программирование. Backtracking нужен там, где либо требуются
сами варианты, либо состояние слишком сложное, чтобы его запоминать (как
в ферзях).

## Дерево решений и оценка сложности

Любой backtracking полезно сначала нарисовать. **Узел** — недостроенный ответ,
**ребро** — один выбор, **лист** — готовый ответ или тупик. Вот дерево для
перестановок массива `[5, 2, 8]`:

```text
                              []
            ┌─────────────────┼─────────────────┐
           [5]               [2]               [8]
        ┌───┴───┐         ┌───┴───┐         ┌───┴───┐
      [5,2]   [5,8]     [2,5]   [2,8]     [8,5]   [8,2]
        │       │         │       │         │       │
     [5,2,8] [5,8,2]   [2,5,8] [2,8,5]   [8,5,2] [8,2,5]
```

Рекурсия обходит это дерево в глубину, слева направо. Код при этом хранит
не дерево, а только **путь от корня до текущего узла** — отсюда память O(глубина).

**Сложность считается через листья.** Рабочая формула:

```text
время ≈ (число листьев) × (работа в листе) , память ≈ глубина дерева
```

Внутренние узлы обычно можно не считать отдельно: в дереве, где каждый узел
ветвится хотя бы надвое, их меньше, чем листьев, а у перестановок их суммарно
меньше e · n! — константа, а не новый порядок.

| Дерево | Ветвление | Глубина | Листьев | Время с копированием ответа |
|---|---|---|---|---|
| перестановки | n, n − 1, …, 1 | n | n! | O(n · n!) |
| подмножества (брать / не брать) | 2 | n | 2ⁿ | O(n · 2ⁿ) |
| буквы на кнопках | 3–4 | n | ≤ 4ⁿ | O(n · 4ⁿ) |
| сумма с повторами | ≤ n | ≤ target / min | ≤ n^(target/min) | экспонента, см. ниже |
| ферзи | ≤ n, ≤ n − 1, … | n | ≤ n! | O(n!) — грубо сверху |

Множитель n в листе — это `path.copy()` или `"".join(...)`. Забыть его — частая
неточность в ответе про сложность.

## Четыре приёма

### 1. Choose → explore → unchoose (выбрать → рекурсия → отменить выбор)

Единый шаблон, в который укладываются все задачи темы. Состояние **одно на всю
рекурсию**, поэтому всё, что сделано перед рекурсивным вызовом, после него
должно быть отменено — зеркально, в обратном порядке.

```python
def backtrack(state):
    if ответ_готов(state):
        result.append(копия(state))      # копия обязательна!
        return
    for choice in варианты(state):
        if not допустим(choice, state):  # отсечение
            continue
        применить(choice, state)         # выбрать
        backtrack(state)                 # рекурсия
        откатить(choice, state)          # отменить выбор
```

Инвариант, который стоит держать в голове: **после возврата из `backtrack`
состояние точно такое же, как до вызова**. Именно поэтому цикл может спокойно
пробовать следующий вариант.

Альтернатива — передавать в рекурсию новую копию (`path + [x]`). Отменять тогда
нечего, но каждый узел стоит O(n) времени и памяти. Вариант рабочий,
если помнить об этой цене.

### 2. Include / exclude (брать / не брать)

Когда ответ — подмножество, удобнее не цикл по вариантам, а **бинарное** дерево:
уровень `i` решает судьбу элемента `i`. Дерево для `[4, 9]`:

```text
                     []                   решаем про 4
           ┌─────────┴─────────┐
      не брать 4             брать 4
          []                  [4]         решаем про 9
      ┌────┴────┐          ┌────┴────┐
     []        [9]        [4]      [4,9]
```

```python
def decide(i):
    if i == len(nums):
        result.append(chosen.copy())
        return
    decide(i + 1)                # не брать — отменять нечего
    chosen.append(nums[i])       # брать
    decide(i + 1)
    chosen.pop()
```

Все 2ⁿ листьев различны, потому что различны пути к ним: два листа расходятся
хотя бы в одном решении «брать / не брать».

### 3. Start index (стартовый индекс против дубликатов)

Если порядок элементов в ответе **не важен**, наивный цикл «попробуй каждый
элемент» выдаст одно и то же по многу раз: `[2, 5]` и `[5, 2]`. Лекарство —
договориться, что ответ строится **только слева направо по индексам**: рекурсия
получает `start` и не смотрит на элементы левее.

```text
nums = [2, 3, 5], собираем пары

без start:  2→3  2→5  3→2  3→5  5→2  5→3     шесть путей, три дубликата
со start:   2→3  2→5  3→5                     каждый набор ровно один раз
```

```python
def backtrack(start):
    ...
    for i in range(start, len(nums)):
        path.append(nums[i])
        backtrack(i + 1)     # i + 1 — элемент используется один раз
        # backtrack(i)       # i     — элемент можно брать повторно
        path.pop()
```

Почему это работает: у любого набора есть ровно одна запись в порядке
возрастания индексов, и дерево со `start` содержит только такие записи.
Дубликаты не отфильтровываются постфактум — они **вообще не порождаются**.
Сравните с «сложить всё в `set` отсортированных кортежей»: результат тот же,
а работы в разы больше.

Перестановкам стартовый индекс не нужен — там порядок как раз важен, и вместо
него работает отметка «занят».

### 4. Pruning (отсечения)

Отсечение — проверка, которая позволяет не входить в поддерево. Правило одно:
отсекать можно только то, где ответа **гарантированно** нет.

```python
for i in range(start, len(candidates)):
    if candidates[i] > remaining:
        break            # кандидаты отсортированы → дальше только хуже
    ...
```

Три уровня силы:

- **`continue`** — этот вариант не годится, остальные ещё могут (клетка под боем);
- **`break`** — не годится этот и все следующие; нужен порядок, обычно сортировка;
- **`return` до цикла** — не годится весь узел (остаток суммы стал отрицательным).

Чем выше по дереву сработало отсечение, тем больше листьев оно срезало. Поэтому
проверку делают **в момент выбора**, а не в листе: проверять расстановку ферзей,
когда все n уже стоят, — это обычный полный перебор.

Отсечения не улучшают оценку в худшем случае, но на практике решают всё:
у 8 ферзей 8! = 40 320 перестановок столбцов, а узлов в дереве с отсечениями —
около двух тысяч.

### Все перестановки

**Условие.** Дан массив различных чисел. Вернуть все его перестановки
в любом порядке.

**Идея.** Позиции заполняются слева направо. На каждом уровне в текущую позицию
можно поставить любой элемент, которого ещё нет в пути. Чтобы узнавать это за
O(1), а не поиском по пути, держим массив отметок `taken`. Выбор — это два
действия (`taken[i] = True`, `path.append`), значит, и отмена — два действия.

**Почему ответ полный и без повторов.** Каждая перестановка — это ровно один
путь от корня: первый элемент однозначно задаёт ветку на первом уровне, второй —
на втором и так далее. Разные пути дают разные перестановки, потому что элементы
различны.

**Сложность.** Листьев n!, в каждом копируем путь длины n — O(n · n!).
Дерево — то самое, что нарисовано выше; вот его обход:

```text
nums = [5, 2, 8]

path = [5]        taken = [x . .]
path = [5, 2]     taken = [x x .]
path = [5, 2, 8]  → в ответ, pop 8, pop 2
path = [5, 8]     taken = [x . x]
path = [5, 8, 2]  → в ответ, pop 2, pop 8, pop 5
path = [2]        taken = [. x .]
...
ответ: [5,2,8] [5,8,2] [2,5,8] [2,8,5] [8,5,2] [8,2,5]
```

**Если спросят про дубликаты во входе** (LeetCode 47): сортируем и на одном
уровне не ставим значение, равное предыдущему, если предыдущее сейчас свободно.

### Все подмножества

**Условие.** Дан массив различных чисел. Вернуть все его подмножества,
включая пустое и сам массив.

**Идея.** Бинарное дерево «брать / не брать» из приёма 2: глубина n, листьев 2ⁿ,
каждый лист — подмножество. Порядок чисел внутри подмножества совпадает
с порядком в исходном массиве, потому что элементы рассматриваются по очереди.

```text
nums = [4, 9]          (сначала ветка «не брать», потом «брать»)

не брать 4 → не брать 9 → []
           →    брать 9 → [9]
   брать 4 → не брать 9 → [4]
           →    брать 9 → [4, 9]
```

**Два других способа — полезно упомянуть.**

- Цикл со стартовым индексом, где **каждый узел**, а не только лист, идёт
  в ответ. Узлов тогда ровно 2ⁿ, и это тот же шаблон, что в задаче про сумму.
- Битовые маски: числа от 0 до 2ⁿ − 1, бит `i` означает «элемент `i` взят».
  Рекурсии нет совсем, но отсечения туда не встроить.

### Число расстановок n ферзей

**Условие.** Сколькими способами можно поставить n ферзей на доску n×n так,
чтобы никакие два не били друг друга. Сами расстановки не нужны, только число.

**Идея.** В каждой строке должен стоять ровно один ферзь, поэтому уровень
дерева — строка, а выбор — столбец. Конфликт по строкам исключён построением,
остаются столбцы и диагонали. Главная находка — как проверить диагональ за O(1):

```text
row - col постоянна на «\»        row + col постоянна на «/»

  0 -1 -2 -3                        0  1  2  3
  1  0 -1 -2                        1  2  3  4
  2  1  0 -1                        2  3  4  5
  3  2  1  0                        3  4  5  6
```

Три множества — занятые столбцы, разности и суммы — заменяют просмотр всей
доски. Саму доску хранить не нужно вовсе. Поставить ферзя — добавить три числа,
снять — удалить те же три.

**Сложность.** В первой строке n вариантов, во второй — не больше n − 1
(столбец занят), в третьей — не больше n − 2… Отсюда верхняя оценка O(n!).
Диагонали режут дерево гораздо сильнее, но аккуратной формулы для этого нет —
достаточно честно назвать O(n!) «оценкой сверху».

```text
n = 4 (номера столбцов с нуля)

row 0: col 0
  row 1: col 2
    row 2: все клетки под боем        ← тупик, снимаем ферзя с (1, 2)
  row 1: col 3
    row 2: col 1
      row 3: все клетки под боем      ← тупик
row 0: col 1
  row 1: col 3
    row 2: col 0
      row 3: col 2                    ← решение [1, 3, 0, 2]
row 0: col 2
  row 1: col 0
    row 2: col 3
      row 3: col 1                    ← решение [2, 0, 3, 1]
row 0: col 3                          зеркально ветке col 0 — решений нет
                                                          итого: 2
```

**Значения для самопроверки:** 1, 0, 0, 2, 10, 4, 40, 92 для n от 1 до 8.
Обратите внимание, что для n = 6 решений меньше, чем для n = 5.

**Оптимизация, если попросят:** доска симметрична, так что можно перебрать
первую строку только до середины и удвоить результат (центральный столбец при
нечётном n считается отдельно).

### Комбинации с заданной суммой

**Условие.** Даны различные положительные числа и `target`. Вернуть все наборы
с суммой `target`; каждое число можно брать сколько угодно раз; наборы,
отличающиеся только порядком, считаются одним.

**Идея.** Два приёма сразу.

- *Start index.* В рекурсию передаём `index`, а не `index + 1`: текущее число
  можно взять ещё раз, а вот вернуться к числам левее нельзя. Поэтому каждая
  комбинация порождается один раз — в неубывающем порядке.
- *Pruning.* Сортируем кандидатов. Как только очередной больше остатка, все
  следующие тоже больше — `break`.

**Почему рекурсия конечна.** Каждый выбор уменьшает остаток хотя бы на
`min(nums) ≥ 1`. С нулём во входе это сломалось бы — решение его не принимает.

```text
nums = [2, 3, 5], target = 9

+2 (остаток 7)
  +2 (остаток 5)
    +2 (остаток 3)
      +2 (остаток 1)   → 2 > 1, break
      +3 (остаток 0)   ✓ [2, 2, 2, 3]
      5 > 3            → break
    +3 (остаток 2)     → 3 > 2, break
    +5 (остаток 0)     ✓ [2, 2, 5]
  +3 (остаток 4)
    +3 (остаток 1)     → 3 > 1, break
    5 > 4              → break
  +5 (остаток 2)       → 5 > 2, break
+3 (остаток 6)
  +3 (остаток 3)
    +3 (остаток 0)     ✓ [3, 3, 3]
    5 > 3              → break
  +5 (остаток 1)       → 5 > 1, break
+5 (остаток 4)         → 5 > 4, break
```

Заметьте: после `+3` двойка больше не рассматривается, поэтому `[3, 2, 2, 2]`
и `[2, 5, 2]` не появляются.

### Буквы телефонной клавиатуры

**Условие.** Дана строка из цифр 2–9. Вернуть все буквенные строки, которые ей
соответствуют на кнопочном телефоне (2 — abc, 3 — def, …, 7 — pqrs, 9 — wxyz).
Для пустой строки ответ — пустой список.

**Идея.** Самое «чистое» дерево в теме: уровень — цифра, ветки — её буквы,
ограничений нет, отсекать нечего. По сути это декартово произведение
(`itertools.product`), записанное рекурсией. Текущую строку держим списком
символов: `append` / `pop` стоят O(1), а склейка происходит только в листе.

```text
digits = "47"        4 → ghi, 7 → pqrs

g → gp gq gr gs
h → hp hq hr hs
i → ip iq ir is                      3 · 4 = 12 строк
```

**Сложность.** Листьев — произведение размеров кнопок, не больше 4ⁿ; в каждом
склейка за O(n).

**Граничный случай.** Без отдельной проверки пустой вход дал бы `[""]` — один
лист в корне. По условию нужен `[]`, поэтому проверка стоит до рекурсии.

## Типичные ошибки

- **`result.append(path)` без копии.** В ответе окажется n! ссылок на один и тот
  же список, к концу работы пустой. Самая частая ошибка темы.
- **Забытая или неполная отмена.** Выбор из трёх действий — отмена тоже из трёх.
  В ферзях легко снять столбец и забыть про диагональ.
- **Отмена не там.** `pop()` должен стоять сразу после рекурсивного вызова внутри
  цикла, а не после цикла и не в базовом случае.
- **`i + 1` вместо `i`** (или наоборот) в стартовом индексе: первое запрещает
  повторное использование, второе разрешает. Перепутав, получите либо неполный
  ответ, либо бесконечную рекурсию там, где остаток не уменьшается.
- **`start + 1` вместо `i + 1`.** Коварная опечатка: код работает, но выдаёт
  дубликаты и лишние наборы.
- **`break` без сортировки.** Отсечение «дальше только хуже» верно лишь для
  упорядоченных кандидатов; без сортировки теряются ответы.
- **Проверка ограничений только в листе.** Ответ верный, но отсечений нет —
  это уже не backtracking, а полный перебор.
- **Перепутанные диагонали.** `row - col` и `row + col` — две разные диагонали,
  нужны обе. Модуль `abs(row - col)` склеивает разные диагонали в одну.
- **Дедупликация через `set` постфактум.** Работает, но порождает в разы больше
  работы и выдаёт непонимание структуры дерева.
- **Пустой вход.** Перестановок пустого массива — одна (`[[]]`), подмножеств —
  одно, а буквенных сочетаний пустой строки — ноль. Это стоит уточнять в условии.
- **Сложность «O(2ⁿ)» без множителя n.** Копирование ответа в листе тоже работа.

## Запуск тестов

```bash
pytest 14-backtracking
```
