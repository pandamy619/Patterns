# 13. Graphs (графы)

## Суть в двух предложениях

Граф — это «вещи и связи между ними»: вершины и рёбра. Почти любая задача
на графах решается в два шага: сначала **увидеть граф** (что здесь вершина,
что ребро, и не спрятан ли он в матрице или в наборе слов), затем **подобрать
обход под вопрос** — достижимость, кратчайший путь, порядок, группы или
самая дешёвая сеть.

Алгоритмов при этом немного — шесть штук, и каждый отвечает на свой тип
вопроса. Вся тема — про то, как не перепутать, какой из них нужен.

## Как узнать паттерн

- в условии есть **объекты и попарные отношения**: дороги, знакомства,
  зависимости, «можно превратить одно в другое»;
- дана **матрица**, а ходить разрешено в соседние клетки — это граф,
  просто рёбра не выписаны;
- спрашивают про **достижимость**, число **групп/областей**, **кратчайший путь**,
  **допустимый порядок**, **наличие цикла**, **минимальную стоимость соединения**;
- состояние можно за один шаг превратить в несколько других (слово → слово,
  позиция → позиция), и нужен минимум шагов;
- наивное решение — «для каждого перебрать всех, потом ещё раз всех»,
  и оно зацикливается, если не помнить посещённое.

Контрпример: данные линейные, а «соседи» — это просто элементы `i - 1` и `i + 1`
(максимальная сумма подмассива, окно длины k). Граф тут увидеть можно, но обход
с `visited` — лишняя тяжесть: хватит указателей, окна или DP по индексу.

## Как хранить граф

| Представление | Как выглядит | Память | «Соседи v» | «Есть ли ребро u–v» | Когда брать |
|---|---|---|---|---|---|
| Список смежности | `adj[v] = [соседи]` | O(n + e) | O(deg v) | O(deg v) | почти всегда; разреженные графы |
| Матрица смежности | `has[u][v] = True` | O(n²) | O(n) | O(1) | плотный граф, мало вершин, частые проверки ребра |
| Список рёбер | `[(u, v, w), …]` | O(e) | O(e) | O(e) | Краскал, Union-Find: рёбра нужны по одному |
| Неявный граф | рёбра вычисляются на лету | O(1) сверх входа | по правилу | по правилу | сетка, слова, состояния игры |

Вход чаще всего приходит списком рёбер — первым делом превращаем его в список
смежности:

```python
adjacency = [[] for _ in range(n)]
for u, v in edges:
    adjacency[u].append(v)
    adjacency[v].append(u)      # для ориентированного графа эту строку убрать
```

В неявном графе на сетке соседей даёт четвёрка смещений:

```python
DIRECTIONS = ((-1, 0), (1, 0), (0, -1), (0, 1))
for dr, dc in DIRECTIONS:
    nr, nc = r + dr, c + dc
    if 0 <= nr < rows and 0 <= nc < cols and подходит(nr, nc):
        ...
```

Обозначения сложности ниже: `n` — вершины, `e` — рёбра, для матрицы —
`m × n` клеток (и не больше `4·m·n` рёбер, поэтому обход сетки — O(m·n)).

## Какой приём для какого вопроса

| Вопрос в условии | Приём | Сложность |
|---|---|---|
| Достижима ли вершина? Обойти/скопировать всё | DFS или BFS | O(n + e) |
| Сколько отдельных областей (компонент)? | DFS/BFS из каждой непосещённой вершины | O(n + e) |
| Можно ли разбить на две группы без рёбер внутри? | DFS/BFS с раскраской | O(n + e) |
| Минимум **шагов**, все рёбра равноценны | BFS | O(n + e) |
| Минимум шагов от **ближайшего из нескольких** стартов; «за сколько волна дойдёт до всех» | multi-source BFS | O(n + e) |
| Минимум шагов, известны и старт, и финиш, граф разрастается быстро | bidirectional BFS | O(n + e), на практике быстрее |
| Лучший путь в графе **без циклов** (DAG) | DFS + мемоизация | O(n + e) |
| Есть ли допустимый порядок? Есть ли цикл в ориентированном графе? | topological sort | O(n + e) |
| Рёбра **добавляются по ходу**, а между ними спрашивают «вместе ли?» и «сколько их?» | Union-Find | ≈ O(1) на операцию |
| Кратчайший путь, у рёбер **разный неотрицательный вес** | Dijkstra | O((n + e) log n) |
| Соединить **всё** с минимальной суммарной стоимостью | MST: Краскал или Прим | O(e log e) |

Две развилки, на которых ошибаются чаще всего:

- **BFS или Dijkstra?** Веса одинаковые — BFS. Разные — Dijkstra. Есть
  отрицательные — ни тот ни другой (нужен Беллман — Форд).
- **DFS/BFS или Union-Find?** Граф дан целиком и спрашивают один раз — обход.
  Рёбра приходят потоком, вопросы вперемешку с ними — Union-Find, потому что
  перезапускать обход после каждого ребра слишком дорого.

## Шесть приёмов

### 1. DFS (обход в глубину)

Идём по ребру, пока есть куда, потом возвращаемся к последней развилке.
Главный и единственный обязательный атрибут — **отметка «посещено»**: без неё
любой цикл превращает обход в бесконечный.

```text
    1 ─── 2         порядок DFS из 1:   1 → 2 → 4 → 5 → 3
    │     │
    3     4 ─── 5   (сначала до упора вглубь: 1-2-4-5,
                     и только потом возвращаемся за вершиной 3)
```

```python
def dfs(node):
    visited.add(node)
    for neighbor in adjacency[node]:
        if neighbor not in visited:
            dfs(neighbor)

# Компоненты связности: обход из каждой ещё не посещённой вершины.
components = 0
for node in range(n):
    if node not in visited:
        components += 1
        dfs(node)
```

Рекурсивный DFS в Python упирается в лимит глубины (по умолчанию 1000 вызовов).
Если путь может быть длинным — сетка 300 × 300, цепочка из 10⁵ вершин, —
заменяем рекурсию явным стеком:

```python
stack = [start]
visited.add(start)
while stack:
    node = stack.pop()
    for neighbor in adjacency[node]:
        if neighbor not in visited:
            visited.add(neighbor)       # отмечаем при добавлении, а не при извлечении
            stack.append(neighbor)
```

**DFS + мемоизация.** Если граф — DAG (циклов нет по построению) и нужна
величина вида «лучший путь из вершины», ответ для вершины не зависит от того,
как мы в неё попали. Считаем его один раз и запоминаем — получается DP на графе.

Когда: копирование графа, подсчёт островов, раскраска, поиск цикла, самый
длинный путь в DAG.

### 2. BFS (обход в ширину)

Обходим **слоями**: сначала все вершины на расстоянии 1, потом 2 и так далее.
Отсюда главное свойство: в графе с равноценными рёбрами первое посещение
вершины — кратчайшее.

```text
слой 0:  S
слой 1:  a  b          очередь:  [S] → [a, b] → [b, c] → [c, d] → …
слой 2:  c  d
```

```python
from collections import deque

queue = deque([start])
visited = {start}
steps = 0
while queue:
    for _ in range(len(queue)):         # ровно один слой
        node = queue.popleft()
        if node == target:
            return steps
        for neighbor in adjacency[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    steps += 1
```

Внутренний `for _ in range(len(queue))` нужен, только когда важен номер слоя.
`list.pop(0)` вместо `deque.popleft()` превращает O(n) в O(n²).

**Multi-source BFS (несколько источников).** Если волна расходится сразу из
нескольких точек, кладём в очередь **все** источники до начала цикла. Это то же
самое, что добавить фиктивную вершину, соединённую со всеми источниками, и
запустить обычный BFS из неё. Каждая клетка получает расстояние до *ближайшего*
источника — за один обход, а не за k обходов.

```text
t=0        t=1        t=2
2 1 1      2 2 1      2 2 2
1 1 1  →   2 1 2  →   2 2 2       два очага (2) стартуют одновременно
1 1 2      1 2 2      2 2 2
```

```python
queue = deque(все_источники)
visited = set(все_источники)
# дальше — обычный послойный BFS
```

**Bidirectional BFS (двунаправленный).** Известны и старт, и финиш — пускаем
две волны навстречу и останавливаемся, когда они соприкоснутся. Если у вершины
в среднем `b` соседей, а ответ равен `d`, обычный BFS посетит порядка `b^d`
вершин, двунаправленный — около `2·b^(d/2)`.

```python
front, back = {start}, {target}
while front and back:
    if len(front) > len(back):
        front, back = back, front       # расширяем меньший фронт
    следующий = set()
    for node in front:
        for neighbor in соседи(node):
            if neighbor in back:
                return длина
            if neighbor not in visited:
                следующий.add(neighbor)
    visited |= следующий
    front = следующий
```

Работает только в неориентированном графе (или если умеем ходить по рёбрам
в обратную сторону).

### 3. Topological sort (топологическая сортировка)

Порядок вершин ориентированного графа, в котором каждое ребро смотрит «слева
направо». Существует тогда и только тогда, когда в графе **нет цикла**, — поэтому
тот же алгоритм служит детектором циклов.

Алгоритм Кана: вершину можно брать, когда у неё не осталось невыполненных
зависимостей, то есть входящая степень равна нулю.

```text
0 ──► 1 ──► 3 ──► 4        in-degree:  0:0  1:1  2:1  3:2  4:1
│           ▲
└───► 2 ────┘              порядок: 0, 1, 2, 3, 4
```

```python
indegree = [0] * n
for u, v in edges:              # ребро u -> v: «u раньше v»
    adjacency[u].append(v)
    indegree[v] += 1

queue = deque(v for v in range(n) if indegree[v] == 0)
order = []
while queue:
    node = queue.popleft()
    order.append(node)
    for neighbor in adjacency[node]:
        indegree[neighbor] -= 1
        if indegree[neighbor] == 0:
            queue.append(neighbor)

есть_цикл = len(order) < n
```

Множество `visited` здесь не нужно: вершина попадает в очередь ровно один раз —
в момент, когда её счётчик обнулился.

Альтернатива — DFS с тремя состояниями вершины («не видели / в работе /
готова»): ребро в вершину «в работе» означает цикл. Кан проще объяснять и
в нём нет рекурсии.

### 4. Union-Find (система непересекающихся множеств)

Структура для двух операций: `union(x, y)` — слить множества, `find(x)` —
назвать представителя множества. «В одной ли группе x и y» — это
`find(x) == find(y)`.

Внутри — лес: каждое множество хранится деревом, представитель — корень.

```text
parent = [0, 0, 0, 2, 4, 4]

      0          4
     / \         |           find(3): 3 → 2 → 0      корень 0
    1   2        5           find(5): 5 → 4          корень 4
        |
        3
```

Без эвристик дерево может выродиться в цепочку, и `find` станет O(n). Лечится
двумя приёмами, которые используют вместе:

- **union by size** — меньшее дерево подвешиваем к корню большего. Глубина
  вершины растёт, только когда её множество хотя бы удваивается, — значит,
  не больше log n раз.
- **path compression** — после `find` все пройденные вершины перевешиваем
  прямо на корень.

```python
def find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])     # сжатие пути
    return parent[x]

def union(x, y):
    rx, ry = find(x), find(y)
    if rx == ry:
        return False
    if size[rx] < size[ry]:
        rx, ry = ry, rx
    parent[ry] = rx                     # меньшее — под большее
    size[rx] += size[ry]
    return True
```

С обеими эвристиками операция стоит амортизированно O(α(n)), где α — обратная
функция Аккермана; для любых мыслимых n она не больше 4, поэтому
говорят «практически константа».

Ограничение: Union-Find умеет только **сливать**. Удаление рёбер он
не поддерживает.

### 5. Dijkstra (алгоритм Дейкстры)

Кратчайшие пути от одной вершины при **неотрицательных** весах. По сути это BFS,
в котором обычную очередь заменили кучей: следующей обрабатывается не самая
«старая» вершина, а самая близкая.

```python
import heapq

distance = [INF] * n
distance[start] = 0
heap = [(0, start)]
while heap:
    dist, node = heapq.heappop(heap)
    if dist > distance[node]:
        continue                        # устаревшая запись
    for neighbor, weight in adjacency[node]:
        candidate = dist + weight
        if candidate < distance[neighbor]:
            distance[neighbor] = candidate
            heapq.heappush(heap, (candidate, neighbor))
```

Почему это корректно: вершина, извлечённая из кучи с актуальным расстоянием, —
ближайшая из необработанных. Любой другой путь к ней шёл бы через вершину
не ближе и дальше только удлинялся бы, ведь рёбра неотрицательные. Одно
отрицательное ребро ломает именно это рассуждение.

В `heapq` нет операции «уменьшить ключ», поэтому в кучу кладём новую запись,
а старую узнаём при извлечении по условию `dist > distance[node]` и пропускаем
(«ленивое удаление»). В куче не больше `e` записей, отсюда O((n + e) log n).

### 6. MST (минимальное остовное дерево)

Остовное дерево — набор из `n − 1` ребра, который связывает все `n` вершин;
минимальное — с наименьшей суммой весов. Оба классических алгоритма жадные
и опираются на одно свойство: **самое дешёвое ребро, пересекающее любой разрез
графа на две части, можно смело брать**.

**Kruskal (Краскал).** Сортируем рёбра по весу и берём каждое, которое
не замыкает цикл. «Замыкает ли цикл» — это вопрос «в одной ли компоненте
концы», то есть ровно Union-Find.

```python
edges.sort()                            # (вес, u, v)
components = UnionFind(n)
total = used = 0
for weight, u, v in edges:
    if components.union(u, v):          # False — концы уже связаны
        total += weight
        used += 1
        if used == n - 1:
            break
```

**Prim (Прим).** Растим одно дерево из произвольной вершины, каждый раз
присоединяя ближайшую к дереву вершину. С кучей — O(e log n), как Дейкстра;
для плотного графа выгоднее вариант на массиве за O(n²) без хранения рёбер.

| | Краскал | Прим (массив) |
|---|---|---|
| Время | O(e log e) | O(n²) |
| Память | O(e) | O(n) |
| Хорош для | разреженного графа, готового списка рёбер | плотного/полного графа |

### Глубокая копия графа

**Условие.** Дана ссылка на вершину связного неориентированного графа; у вершины
есть значение (все значения разные) и список соседей. Построить полностью
независимую копию графа и вернуть копию этой вершины. Для `None` вернуть `None`.

**Идея.** Обходим оригинал в глубину и по пути создаём копии. Вся сложность —
в циклах: от вершины 1 мы придём в 2, а у той в соседях снова 1. Поэтому держим
словарь `оригинал → копия`. Он делает сразу две вещи: работает как `visited`
и гарантирует, что у каждой вершины **ровно одна** копия, сколько бы путей
к ней ни вело.

**Тонкость.** Копию нужно положить в словарь **до** обхода соседей. Иначе сосед,
вернувшись по обратному ребру, не найдёт её и начнёт копировать заново —
бесконечная рекурсия.

```text
граф:  1 ─ 2        соседи: 1:[2,3]  2:[1,3]  3:[1,2,4]  4:[3]
       │ ╱
       3 ─ 4

clone(1)  создаём 1'
  clone(2)  создаём 2'
    clone(1)  уже есть → 1'
    clone(3)  создаём 3'
      clone(1)  уже есть → 1'
      clone(2)  уже есть → 2'
      clone(4)  создаём 4'
        clone(3)  уже есть → 3'
  clone(3)  уже есть → 3'
```

Каждая вершина создаётся один раз, каждое ребро просматривается дважды (с обоих
концов) — O(n + e).

### Сколько островов

**Условие.** Матрица из 0 (вода) и 1 (суша). Остров — группа единиц, соединённых
по вертикали и горизонтали (диагональ не считается). Вернуть число островов.

**Идея.** Это подсчёт компонент связности в неявном графе: клетка суши — вершина,
ребро — общая сторона. Идём по матрице; встретили непосещённую единицу —
это новый остров: увеличиваем счётчик и обходом «заливаем» весь остров, чтобы
больше на него не наткнуться.

**Почему счётчик не ошибается.** Обход из клетки помечает *всю* её компоненту.
Значит, любая непомеченная единица принадлежит острову, которого мы ещё
не видели.

```text
1 0 0 1 1        A . . B B        острова в порядке обнаружения:
1 0 1 0 1   →    A . C . B        A (0,0)   B (0,3)   C (1,2)
0 0 1 0 0        . . C . .        D (3,0)   E (3,4)
1 1 0 0 1        D D . . E        ответ: 5
```

**Детали реализации.** В решении обход сделан на явном стеке: рекурсия на поле
300 × 300 из одних единиц падает с `RecursionError` (такой тест есть). Отметки
лежат в отдельной таблице, вход не портится; если затирать
единицы нулями допустимо — память под отметки не нужна.

### Заражение матрицы

**Условие.** Клетки матрицы: `0` — пусто, `1` — здоровая, `2` — заражённая.
Каждую секунду заражённая клетка заражает здоровых соседей по четырём сторонам.
Через сколько секунд здоровых не останется? Если кто-то недостижим — вернуть −1.
Если здоровых нет изначально — 0.

**Идея.** Время заражения клетки — расстояние до **ближайшего** очага. Запускать
BFS от каждого очага отдельно и брать минимум — O(k·m·n). Multi-source BFS
кладёт в очередь все очаги сразу и получает те же минимумы за один проход.
Ответ — номер последнего слоя, в котором кого-то заразили.

**Как узнать про −1.** Заранее считаем здоровые клетки и уменьшаем счётчик при
каждом заражении. Остался не ноль — кто-то отгорожен пустотой.

```text
вход           секунда заражения (· — пусто)
2 1 1 0        0 1 2 ·
0 1 0 1   →    · 2 · 1        последней заражается клетка (2,0) — ответ 3
1 1 1 2        3 2 1 0
```

Клетку (1,1) левый очаг достаёт за 2 секунды, правый — только за 3; с клеткой
(2,1) всё наоборот. В таблице везде минимум: кто первым дошёл, тот и пометил.

**Тонкость.** Цикл идёт, пока `healthy > 0`. Без этого условия последний слой
(которому заражать уже некого) добавит лишнюю секунду.

### Двудольный ли граф

**Условие.** Неориентированный граф задан списком смежности: `graph[i]` — соседи
вершины `i`. Можно ли покрасить вершины в два цвета так, чтобы концы каждого
ребра были разноцветными? Граф может быть несвязным.

**Идея.** Красим жадно: стартовой вершине — любой цвет, каждому соседу —
противоположный. Выбора нигде нет, все цвета в компоненте **вынужденные**.
Поэтому если наткнулись на соседа, уже покрашенного в наш цвет, — виновата
не неудачная раскраска, а сам граф: в нём есть цикл нечётной длины.

**Почему стартовый цвет не важен.** У связной двудольной компоненты ровно две
правильные раскраски, и они зеркальны. Компоненты между собой не связаны,
так что красим каждую независимо — отсюда внешний цикл по всем вершинам.

```text
graph = [[1,3], [0,2], [1,3,4], [0,2], [2,5], [4]]      (+ и − — два цвета)

0:+   из 0: 1 → −, 3 → −   из 1: 2 → +   из 2: 4 → −   из 4: 5 → +
цвета: [+, −, +, −, −, +] — конфликтов нет → True

graph = [[1,2], [0,2], [0,1,3], [2]]                    треугольник 0-1-2 с хвостом
0:+   из 0: 1 → −, 2 → −   из 1: сосед 2 тоже «−» → False
```

### Самый длинный возрастающий путь

**Условие.** Матрица положительных чисел. Путь — последовательность клеток, где
каждая следующая соседствует с предыдущей по стороне и **строго больше** её.
Найти наибольшую возможную длину пути (в клетках).

**Идея.** Проведём ребро из клетки в каждого большего соседа. Цикл в таком графе
невозможен — числа вдоль пути только растут, — значит, это DAG. В DAG
«длина лучшего пути, начинающегося в клетке» определена однозначно:

```text
best(клетка) = 1 + max(best(сосед) для соседей со значением больше), либо 1
```

Голый DFS из каждой клетки экспоненциален; с таблицей `best` каждая клетка
считается один раз — O(m·n). Отдельный `visited` не нужен: строгое неравенство
само не даёт вернуться назад.

```text
матрица        best (длина лучшего пути ИЗ клетки)
6 2 9          2 6 1
7 3 8     →    1 5 2          ответ 6:  2 → 3 → 4 → 5 → 8 → 9
1 4 5          5 4 3
```

Порядок заполнения у рекурсии — «от вершин к подножию»: сначала получают
значения локальные максимумы (7 и 9 — по единице), последними — клетки,
с которых начинаются длинные пути.

**Без рекурсии.** Путь может пройти через все клетки («змейка» 100 × 100 —
глубина 10 000), и рекурсия упрётся в лимит. В файле есть второй вариант:
сортируем клетки по убыванию значения и считаем `best` в этом порядке — все
большие соседи к нужному моменту уже готовы. Это топологический порядок,
полученный сортировкой; цена — лишний логарифм.

### Кратчайшая цепочка превращений слова

**Условие.** Даны слова `start`, `end` и словарь слов одинаковой длины из строчных
латинских букв. За шаг меняется ровно одна буква, и каждое слово цепочки
(включая `start` и `end`) должно быть в словаре. Вернуть число **слов**
в кратчайшей цепочке или 0, если её нет.

**Идея.** Слова — вершины, ребро — «отличаются одной буквой», рёбра равноценны,
нужен минимум шагов — это BFS. Граф неявный, и главный вопрос — как искать
соседей. Сравнивать слово со всем словарём — O(n·L) на слово. Дешевле
перебрать все `25·L` вариантов замены одной буквы и проверить каждый в множестве.

Посещённые слова просто удаляем из множества — отдельный `visited` не нужен.

```text
словарь: cold cord card ward warm worm word corm bold        cold → warm

слой 1:  cold
слой 2:  cord  bold
слой 3:  card  word  corm
слой 4:  ward  worm
слой 5:  warm  ← нашли, ответ 5      (cold → cord → card → ward → warm)
```

**Двунаправленный вариант.** Ведём два множества-фронта и каждый раз расширяем
меньшее; как только сосед оказался в чужом фронте — волны встретились.

```text
front = {cold}          back = {warm}          длина 1
расширяем front  →  {cord, bold}               длина 2
расширяем back   →  {ward, worm}               длина 3   (он стал меньшим)
расширяем {ward, worm}  →  {card, word, corm}  длина 4
расширяем {cord, bold}: сосед card лежит во встречном фронте → длина 5
```

**Что стоит уточнить.** Считаем слова или шаги (здесь слова: соседние
слова дают 2)? Обязан ли `start` быть в словаре? В этом конспекте — обязан,
как и любое слово цепочки; в LeetCode 127 — нет. При `start == end` ответ 1.

### Слияние сообществ

**Условие.** Есть `n` человек с номерами `0..n−1`, сначала каждый — сам себе
сообщество. Реализовать `connect(x, y)` — знакомство, после которого сообщества
`x` и `y` сливаются, и `get_community_size(x)` — размер сообщества `x`.
Вызовы идут вперемешку.

**Идея.** Граф меняется на ходу, а вопросы задают между изменениями, — обход
после каждого `connect` стоил бы O(n). Union-Find делает обе операции практически
за O(1). Размер хранится в массиве `size` и имеет смысл **только у корня**:
при слиянии корень-победитель прибавляет размер проигравшего.

```text
n = 6                     parent                  size корней
connect(0, 3)             [0, 1, 2, 0, 4, 5]      {0: 2}
connect(4, 5)             [0, 1, 2, 0, 4, 4]      {0: 2, 4: 2}
connect(3, 5)             [0, 1, 2, 0, 0, 4]      {0: 4}     find(3)=0, find(5)=4 → 4 под 0
connect(0, 4)             без изменений           уже вместе: find(0) = find(4) = 0

get_community_size(5) → find(5): 5 → 4 → 0 → size[0] = 4
                        (заодно 5 перевешивается прямо на 0: parent[5] = 0)
get_community_size(2) → 1
```

**Главная ловушка** — `connect` для уже связанных людей. Без проверки
`root_x == root_y` корень прибавит свой размер к самому себе, и сообщество
«вырастет» вдвое на пустом месте.

В решении `find` написан двумя циклами, без рекурсии: до первого сжатия путь
может оказаться длинным. Класс `UnionFind` переиспользуется в задаче про
соединение точек.

### Можно ли пройти все курсы

**Условие.** Курсы пронумерованы `0..n−1`. Пара `[a, b]` означает: курс `a` нужно
пройти **раньше** курса `b`. Можно ли пройти все курсы?

**Идея.** Рисуем ребро `a → b`. Пройти всё можно ровно тогда, когда в графе нет
цикла: цикл — это набор курсов, каждый из которых ждёт другого. Алгоритм Кана
моделирует учёбу: берём любой курс без невыполненных пререквизитов, «проходим»
его и уменьшаем счётчики у тех, кого он открывал. Если удалось взять все `n` —
ответ `True`.

**Почему цикл ловится.** У вершины на цикле всегда есть входящее ребро от другой
вершины того же цикла, и та тоже никогда не освободится. Их счётчики не дойдут
до нуля, в очередь они не попадут, `taken < n`.

```text
n = 5, пары: [0,1] [0,2] [1,3] [2,3] [3,4]          счётчики: [0, 1, 1, 2, 1]

очередь [0]     берём 0 → счётчики [0, 0, 0, 2, 1]   открылись 1 и 2
очередь [1, 2]  берём 1 → счётчики [0, 0, 0, 1, 1]
очередь [2]     берём 2 → счётчики [0, 0, 0, 0, 1]   открылся 3
очередь [3]     берём 3 → счётчики [0, 0, 0, 0, 0]   открылся 4
очередь [4]     берём 4                              взято 5 из 5 → True

n = 4, пары: [0,1] [1,2] [2,3] [3,1]                счётчики: [0, 2, 1, 1]
очередь [0]     берём 0 → счётчики [0, 1, 1, 1]      никто не открылся
очередь пуста                                        взято 1 из 4 → False
```

**Осторожно с направлением.** В LeetCode 207 пара записана наоборот:
`[курс, его пререквизит]`. Перепутанное направление на ответ «есть ли цикл»
не влияет, но если попросят сам порядок (LeetCode 210) — получите его задом
наперёд.

### Кратчайшие расстояния во взвешенном графе

**Условие.** Вершины `0..n−1`, рёбра `[u, v, w]` — неориентированные,
с неотрицательным весом. Вернуть список расстояний от `start` до каждой вершины;
для недостижимых — −1.

**Идея.** Веса разные, поэтому BFS не годится: путь из трёх лёгких рёбер может
быть короче одного тяжёлого. Дейкстра обрабатывает вершины по возрастанию
расстояния; в кучу кладём пары `(расстояние, вершина)`.

```text
рёбра: 0-1:7  0-2:2  2-1:3  1-3:1  2-3:8  3-4:5      вершина 5 изолирована, start = 0

извлекли    улучшения                 куча после шага
(0, 0)      1 → 7,  2 → 2             (2,2) (7,1)
(2, 2)      1 → 5,  3 → 10            (5,1) (7,1) (10,3)
(5, 1)      3 → 6                     (6,3) (7,1) (10,3)
(6, 3)      4 → 11                    (7,1) (10,3) (11,4)
(7, 1)      устарела: 7 > 5           (10,3) (11,4)
(10, 3)     устарела: 10 > 6          (11,4)
(11, 4)     —                         пусто

ответ: [0, 5, 2, 6, 11, -1]
```

Хорошо видно, зачем нужна проверка на устаревшую запись: вершина 1 попала
в кучу дважды — сначала с 7 (прямое ребро), потом с 5 (через вершину 2).

**Детали.** Кратные рёбра и петли алгоритму не мешают. Недостижимость внутри
алгоритма — это «бесконечность», и на −1 она меняется только в самом конце:
если хранить −1 прямо в массиве расстояний, сравнение `candidate < -1`
никогда не сработает. Если граф по условию ориентированный,
достаточно убрать одну строку при построении списка смежности.

### Соединить все точки

**Условие.** Даны точки на плоскости с целыми координатами. Соединить две точки
стоит `|x₁ − x₂| + |y₁ − y₂|`. Найти минимальную суммарную стоимость, при которой
все точки связаны (напрямую или через другие).

**Идея.** Граф полный — ребро есть между любыми двумя точками, — и нужен самый
дешёвый набор рёбер, связывающий всё. Это MST. По Краскалу: выписываем все
`n(n−1)/2` рёбер, сортируем и берём те, чьи концы ещё в разных компонентах.

**Почему жадность работает.** Пусть ребро соединяет две разные компоненты
и оно самое дешёвое из оставшихся. Любое остовное дерево обязано как-то связать
эти две части; если оно делает это более дорогим ребром, его можно заменить
нашим — связность сохранится, сумма не вырастет.

```text
точки: 0:(0,0)  1:(1,3)  2:(4,0)  3:(5,4)  4:(2,1)

вес  ребро   берём?   сумма
 3   0–4     да         3
 3   1–4     да         6
 3   2–4     да         9
 4   0–1     нет        9      0 и 1 уже связаны через 4
 4   0–2     нет        9
 5   1–3     да        14      взято n − 1 = 4 ребра → стоп
```

**Сложность.** Рёбер O(n²), их сортировка — O(n² log n), память O(n²). Для
полного графа выгоднее Прим на массиве: O(n²) времени и O(n) памяти, рёбра
вообще не хранятся. Он тоже есть в файле (`connect_the_dots_prim`), тесты
сверяют оба варианта друг с другом и с перебором всех остовных деревьев.

## Типичные ошибки

- **Нет отметки «посещено»** — бесконечный цикл на первом же цикле графа.
  В неориентированном графе циклом является уже само ребро: a → b → a.
- **Отметка при извлечении, а не при добавлении в очередь/стек.** Вершина
  попадает в очередь много раз; на сетке это раздувает память и время в разы.
- **`list.pop(0)` вместо `deque.popleft()`** — незаметные O(n) на каждом шаге.
- **Обход только из вершины 0.** Граф бывает несвязным: двудольность, циклы,
  компоненты нужно проверять из каждой непосещённой вершины.
- **Рекурсивный DFS на больших входах** — `RecursionError`. Явный стек или
  хотя бы упоминание проблемы.
- **BFS во взвешенном графе.** Минимум рёбер ≠ минимум суммы весов.
- **Дейкстра с отрицательными весами** — молча выдаёт неверный ответ.
- **Забытая проверка устаревшей записи** в Дейкстре: ответ останется верным,
  но сложность деградирует.
- **Multi-source BFS: источники добавляются по одному** с отдельным запуском —
  теряется весь смысл. И лишняя секунда за последний слой.
- **Union-Find: сравнивать `parent[x] == parent[y]`** вместо `find(x) == find(y)`;
  читать `size[x]` не у корня; не проверять, что корни уже совпали.
- **Топологическая сортировка: перепутано направление ребра.** Держите в голове
  правило: «ребро идёт от того, что раньше, к тому, что позже».
- **Границы сетки.** Проверка `0 <= nr < rows` должна стоять **до** обращения
  к `matrix[nr][nc]`; отрицательный индекс в Python не падает, а молча
  берёт элемент с конца.
