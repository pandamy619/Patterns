# 18. Bit Manipulation (битовые операции)

## Суть в двух предложениях

Целое число — это ещё и массив битов, над которым процессор
умеет работать **целиком за одну операцию**: сравнить, склеить, сдвинуть все
разряды разом. Паттерн состоит в том, чтобы увидеть в задаче такую «параллельную»
операцию над разрядами и заменить ею цикл, хеш-таблицу или массив флагов.

Приёмов немного, и почти все сводятся к двум идеям: **маска** выбирает нужные
разряды, а **XOR** запоминает чётность без дополнительной памяти.

## Как узнать паттерн

- в условии прямо говорится про **двоичную запись**, биты, степени двойки;
- требуют **O(1) памяти** там, где напрашивается множество или счётчик;
- элементы встречаются **парами** (чётное число раз), а искать нужно исключение;
- нужно хранить **набор флагов** для небольшого множества (до 32–64 элементов):
  подмножества, посещённые вершины, занятые столбцы;
- деление и умножение на два, проверка чётности, «является ли степенью двойки»;
- ответ для числа `x` легко выразить через ответ для `x >> 1` или `x & (x - 1)`.

Контрпример: «найти число, которое встречается один раз, когда остальные
встречаются **по три**». Чистый XOR тут не работает — тройка сама себя не гасит.
Нужен либо подсчёт единиц в каждом разряде по модулю 3, либо обычная
хеш-таблица. Битовый трюк — не универсальная замена счётчику.

## Операторы

Примеры — на четырёхбитных числах `a = 1100` (12) и `b = 1010` (10).

| Оператор | Название | Правило для каждого разряда | Пример |
|---|---|---|---|
| `a & b` | AND (И) | 1, только если в обоих 1 | `1100 & 1010 = 1000` |
| `a \| b` | OR (ИЛИ) | 1, если хотя бы в одном 1 | `1100 \| 1010 = 1110` |
| `a ^ b` | XOR (исключающее ИЛИ) | 1, если биты **разные** | `1100 ^ 1010 = 0110` |
| `~a` | NOT (инверсия) | 0 ↔ 1 | `~1100 = 0011` в четырёх разрядах; в Python `~12 == -13` |
| `a << k` | сдвиг влево | дописать `k` нулей справа, то есть умножить на 2ᵏ | `0011 << 2 = 1100` (3 → 12) |
| `a >> k` | сдвиг вправо | отбросить `k` младших разрядов, то есть `a // 2ᵏ` | `1100 >> 2 = 0011` (12 → 3) |

Удобно помнить роли: `&` **вырезает** (оставляет только то, что под маской),
`|` **вклеивает**, `^` **переключает и сравнивает**.

### Особенность Python: у чисел нет ширины

В C или Java `int` — это ровно 32 разряда, лишнее молча отбрасывается.
В Python целые **произвольной длины**, и это меняет три вещи.

```python
~5                        # -6, а не 4294967290: ~x всегда равно -x - 1
~5 & 0xFFFFFFFF           # 4294967290 == 0xFFFFFFFA — «настоящая» 32-битная инверсия
0xFFFFFFFF << 1           # 8589934590 — 33 разряда, ничего не потерялось
(0xFFFFFFFF << 1) & 0xFFFFFFFF   # 4294967294 == 0xFFFFFFFE — как в 32-битном регистре
-8 >> 1                   # -4: сдвиг вправо арифметический, знак сохраняется
```

1. **`~x` отрицательно для любого неотрицательного `x`.** Отрицательное число
   ведёт себя так, будто слева у него бесконечно много единиц. Чтобы получить
   инверсию в 32 разрядах, сразу накладывайте маску: `~x & 0xFFFFFFFF`.
2. **Сдвиг влево ничего не отбрасывает.** Если в задаче число «32-битное»,
   после `<<` результат нужно обрезать той же маской `0xFFFFFFFF`.
3. **Цикл `while x: x >>= 1` на отрицательном `x` бесконечен** — сдвиг
   доходит до `-1` и там останавливается. Либо запрещайте отрицательные числа,
   либо сначала приводите к беззнаковому виду: `x & 0xFFFFFFFF`.

И ещё о приоритетах: сдвиги слабее арифметики, поэтому `1 << 3 + 1` — это
`1 << 4 = 16`, а не 9. Сомневаетесь — ставьте скобки.

## Четыре приёма

### 1. Single-bit masks (маска из одного бита)

`1 << i` — число, у которого единица стоит только в позиции `i` (позиции
считаются справа, с нуля). С ним делается всё, что нужно одному биту.

```python
(x >> i) & 1        # прочитать бит i          — 0 или 1
x & (1 << i)        # то же, но «ноль / не ноль»
x | (1 << i)        # установить бит i в 1
x & ~(1 << i)       # сбросить бит i в 0
x ^ (1 << i)        # переключить бит i
```

```text
x = 101100 (44)      позиции:  5 4 3 2 1 0

прочитать бит 3:   (x >> 3) & 1      = 1
прочитать бит 1:   (x >> 1) & 1      = 0
установить бит 1:  x |  000010       = 101110
сбросить бит 2:    x & ~000100       = 101000
переключить бит 3: x ^  001000       = 100100
```

В сбросе `~(1 << i)` отрицательно, но это не мешает: «бесконечные единицы»
слева в паре с `&` просто сохраняют все старшие разряды `x`.

Когда: множество флагов в одном числе, перебор подмножеств
(`for mask in range(1 << n)`), компактное «посещено / не посещено».

### 2. Lowest set bit (младшая единица)

Вычитание единицы «ломает» число ровно в одном месте: младшая единица
становится нулём, а все нули правее неё — единицами. Левая часть не меняется.

```text
x     = 101100   (44)
x - 1 = 101011   (43)
           ^^^--- изменился только хвост, начиная с младшей единицы

x & (x - 1) = 101000     младшая единица стёрта
x & -x      = 000100     осталась только младшая единица
```

```python
x & (x - 1)                   # убрать младшую единицу
x & -x                        # выделить младшую единицу
x > 0 and x & (x - 1) == 0    # x — степень двойки (единица ровно одна)
```

Почему работает `x & -x`: `-x` — это `~x + 1`. Инверсия переворачивает все
биты, а `+ 1` «прокатывается» по хвосту из единиц и останавливается как раз
на позиции младшей единицы `x`. Левее неё биты `x` и `-x` противоположны,
правее — нули у обоих, совпадает единственный разряд.

Когда: подсчёт единиц за число шагов, равное ответу; проверка степени двойки;
дерево Фенвика; перебор установленных битов маски.

### 3. XOR cancellation (взаимное уничтожение пар)

Четыре свойства, на которых держится приём:

```text
a ^ 0 = a                     ноль ничего не меняет
a ^ a = 0                     число гасит само себя
a ^ b = b ^ a                 порядок не важен
(a ^ b) ^ c = a ^ (b ^ c)     скобки не важны
```

Отсюда следствие: XOR набора чисел зависит только от того, **чётное или
нечётное** число раз встретилось каждое значение. Всё, что встретилось чётное
число раз, исчезает, где бы в массиве оно ни стояло.

```python
acc = 0
for value in data:
    acc ^= value
# в acc — XOR тех значений, что встретились нечётное число раз
```

Ещё два полезных следствия: `a ^ b == 0` равносильно `a == b`, а единицы
в `a ^ b` стоят ровно в тех разрядах, где `a` и `b` различаются (их количество —
расстояние Хэмминга).

Когда: одиночка среди пар, пропущенное число в диапазоне `0..n`
(XOR индексов с XOR значений), «чем отличаются два числа».

### 4. Parallel masks (групповые маски)

Маска с регулярным узором выбирает сразу **целый класс** позиций. Дальше
с классом работают как с одним числом: сдвигают, склеивают с другим классом.
Цикла по битам нет — все разряды обрабатываются одновременно.

```text
0x55555555 = 0101 0101 ... 0101     чётные позиции (0, 2, 4, ...)
0xAAAAAAAA = 1010 1010 ... 1010     нечётные позиции (1, 3, 5, ...)
0x33333333 = 0011 0011 ... 0011     младшая пара в каждой четвёрке
0x0F0F0F0F = 0000 1111 ... 1111     младшая четвёрка в каждом байте
```

```python
group_a = x & MASK_A
group_b = x & MASK_B
result = (group_a << k) | (group_b >> k)
```

Запомнить шестнадцатеричные цифры легко: `5 = 0101`, `A = 1010`, `3 = 0011`,
`F = 1111`.

Когда: обмен соседних битов, разворот битов числа, подсчёт единиц без цикла.

### Количество единиц у всех чисел от 0 до n

**Условие.** Дано неотрицательное `n`. Вернуть список, где на позиции `i` стоит
количество единичных битов в двоичной записи числа `i` — его *вес Хэмминга*, —
для всех `i` от 0 до `n`.

**Идея 1: считать каждое число по битам.** Младший бит — это `x & 1`. Забрали
его, сдвинули число вправо, повторили, пока не останется ноль.

```text
x = 101100 (44)

x = 101100   x & 1 = 0   единиц: 0
x =  10110   x & 1 = 0   единиц: 0
x =   1011   x & 1 = 1   единиц: 1
x =    101   x & 1 = 1   единиц: 2
x =     10   x & 1 = 0   единиц: 2
x =      1   x & 1 = 1   единиц: 3
x =      0   стоп                    → 3
```

На одно число уходит столько шагов, сколько в нём разрядов, — O(log x),
на весь диапазон O(n log n). Вариант с `x &= x - 1` (в файле —
`count_set_bits_kernighan`) делает по шагу на каждую **единицу**, а не на
каждый разряд: для `101100` это три шага вместо шести. Асимптотика в худшем
случае та же, но на разреженных числах заметно быстрее.

**Идея 2: DP.** Числа идут подряд, и считать каждое с нуля расточительно.
Посмотрим, что делает `x >> 1`: отбрасывает последний разряд и больше ничего
не трогает. Значит, единиц в `x` столько же, сколько в `x >> 1`, плюс
отброшенный бит:

```text
weights[x] = weights[x >> 1] + (x & 1)
```

**Почему это корректно.** `x >> 1 < x` для любого `x ≥ 1`, поэтому при обходе
слева направо нужное значение уже лежит в массиве. База — `weights[0] = 0`.
Каждая ячейка заполняется за O(1), итого O(n).

```text
n = 10

 x   двоичн.   x >> 1   weights[x >> 1]   x & 1   weights[x]
 0   0000         —            —            —         0
 1   0001      0 (000)         0            1         1
 2   0010      1 (001)         1            0         1
 3   0011      1 (001)         1            1         2
 4   0100      2 (010)         1            0         1
 5   0101      2 (010)         1            1         2
 6   0110      3 (011)         2            0         2
 7   0111      3 (011)         2            1         3
 8   1000      4 (100)         1            0         1
 9   1001      4 (100)         1            1         2
10   1010      5 (101)         2            0         2

ответ: [0, 1, 1, 2, 1, 2, 2, 3, 1, 2, 2]
```

**Альтернативная рекуррентность.** `weights[x] = weights[x & (x - 1)] + 1`:
число без младшей единицы тоже меньше `x` и уже посчитано. Оба варианта
равноценны; первый проще объяснить, второй показывает, что вы знаете
приём с младшей единицей.

В боевом коде всё это заменяет `x.bit_count()` (Python 3.10+) или
`bin(x).count("1")`, но здесь нас интересует именно механика.

### Число без пары

**Условие.** В непустом массиве каждое значение встречается ровно два раза,
и только одно — один раз. Найти его.

**Очевидные решения.** `Counter` — O(n) времени и O(n) памяти. Сортировка
и сравнение соседей — O(n log n) и порча входа. Хочется O(n) и O(1).

**Идея.** Сворачиваем весь массив XOR'ом. Порядок операндов не важен, поэтому
мысленно можно переставить элементы так, чтобы пары встали рядом: каждая пара
даёт ноль, ноль ничего не меняет, остаётся одиночка.

```text
nums = [6, 9, 4, 9, 6]

acc = 0000
acc ^ 0110 (6) = 0110
acc ^ 1001 (9) = 1111
acc ^ 0100 (4) = 1011
acc ^ 1001 (9) = 0010      девятка погасила девятку
acc ^ 0110 (6) = 0100      шестёрка погасила шестёрку   → 4
```

Промежуточные значения (`1111`, `1011`) сами по себе ничего не значат —
смысл есть только у итога.

**Почему корректно и для отрицательных чисел.** Свойства XOR выполняются для
каждого разряда независимо, а Python для отрицательных чисел ведёт себя так,
будто у них бесконечное дополнение до двух. `[8, -3, 8]` честно даёт `-3`.

**Границы применимости.** Приём опирается на точное условие «все остальные —
чётное число раз». Если одиночек две, XOR вернёт `a ^ b`, и их придётся
разделять по любому различающемуся биту (`diff & -diff`). Если остальные
встречаются по три раза — см. контрпример в начале.

### Поменять местами соседние биты

**Условие.** Дано беззнаковое 32-битное число. Позиции битов считаются от
младшего разряда, с нуля. Нужно поменять бит 0 с битом 1, бит 2 с битом 3
и так далее — все 16 пар — и вернуть результат.

**Наивно.** Пройти циклом по 16 парам, прочитать оба бита, записать наоборот.
Работает, но это 16 итераций там, где хватит трёх операций.

**Идея.** Все чётные биты должны уехать на одну позицию влево, все нечётные —
на одну вправо. Значит, достаточно разделить число на два «слоя», сдвинуть
каждый целиком и сложить обратно:

1. `n & 0x55555555` — слой чётных позиций, остальное обнулено;
2. `n & 0xAAAAAAAA` — слой нечётных;
3. чётный слой `<< 1`, нечётный `>> 1`, затем `|`.

```text
n = 38, показаны младшие 8 разрядов (старшие — нули)

n                 = 0010 0110
n & 0x55555555    = 0000 0100     чётные позиции
n & 0xAAAAAAAA    = 0010 0010     нечётные позиции
чётные  << 1      = 0000 1000
нечётные >> 1     = 0001 0001
|                 = 0001 1001     → 25
```

**Почему слои не мешают друг другу.** После сдвига чётный слой занимает только
нечётные позиции, а нечётный — только чётные. Общих разрядов нет, поэтому
`|` склеивает их без потерь (здесь `|`, `^` и `+` дали бы одно и то же).

**Нужна ли маска `0xFFFFFFFF`.** Именно здесь — нет: старшая чётная позиция —
30-я, после сдвига она станет 31-й и за 32 разряда не выйдет. Но стоит записать
решение иначе — скажем, `(n << 1) & ODD_MASK` — или получить вторую маску как
`~EVEN_MASK`, и особенности Python вылезут наружу: `~0x55555555` равно
`-1431655766`, и только `~0x55555555 & 0xFFFFFFFF` даёт ожидаемое `0xAAAAAAAA`.
Поэтому в решении на входе стоит явная проверка диапазона, а обе маски
записаны константами.

**Проверка на здравый смысл.** Операция обратима: применив её дважды, получаем
исходное число. Это удобный инвариант для тестов.

## Типичные ошибки

- **Забытая ширина числа в Python.** `~x` отрицательно, `x << k` растёт без
  ограничений. В задачах про 32-битные числа обрезайте результат:
  `& 0xFFFFFFFF`.
- **Бесконечный цикл на отрицательном числе.** `while x: x >>= 1` для `x < 0`
  застревает на `-1`. Проверяйте вход или приводите к беззнаковому виду.
- **Приоритеты операторов.** `1 << i + 1` — это `1 << (i + 1)`. А в C, Java
  и JavaScript ещё и `x & 1 == 0` читается как `x & (1 == 0)`; в Python
  сравнение слабее `&`, так что там это работает, но скобки
  `(x & 1) == 0` избавляют от вопросов на любом языке.
- **Перепутанные маски.** `0x55555555` — чётные позиции (младший бит равен 1),
  `0xAAAAAAAA` — нечётные. Если сдвинуть чётный слой вправо, а нечётный влево,
  поменяются не те пары — (1, 2), (3, 4), ..., — бит 0 пропадёт, а бит 31
  уедет в 32-й разряд, которого у 32-битного числа нет.
- **`x & (x - 1) == 0` без проверки на ноль.** Для `x = 0` выражение истинно,
  хотя ноль не степень двойки.
- **XOR там, где условие его не гарантирует.** «Каждое число встречается
  дважды» — ключевая фраза. Если в условии «не более двух раз» или «трижды»,
  приём молча вернёт мусор.
- **Нумерация битов.** Позиции считаются с нуля и справа. «Чётные биты» —
  это 0-й, 2-й, 4-й, а не «второй, четвёртый» в бытовом смысле. Уточните
  это до того, как писать код.
