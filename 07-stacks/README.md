# 07. Stacks (стеки)

## Суть в двух предложениях

Стек отдаёт элементы в порядке, обратном поступлению (LIFO): доступна только
вершина — то, что положили последним. Он нужен там, где **самое свежее
незавершённое дело должно закончиться первым**: последняя открытая скобка
закрывается первой, самое недавнее «ждущее» число первым находит ответ,
внутреннее выражение вычисляется раньше внешнего.

Стек — это память о прошлом, из которой удобно выбрасывать: если свежий
элемент делает часть старых ненужными, они лежат на вершине подряд и снимаются
за O(1) каждый.

## Как узнать паттерн

- в данных есть **вложенность**: скобки, теги, вызовы функций, подвыражения;
- элементы **образуют пары**, и новая пара может возникнуть после исчезновения
  соседней («цепная реакция»);
- для каждого элемента ищем **ближайший справа или слева больший / меньший**;
- нужно **вернуться к отложенному состоянию** ровно в обратном порядке;
- рекурсивное решение очевидно, но просят итеративное — стек вызовов
  заменяется явным стеком;
- наивное решение для каждого элемента заново просматривает соседей — O(n²).

Контрпример: обработка в порядке поступления — задачи в очереди на исполнение,
обход графа в ширину. Там первым должен выйти самый **старый** элемент, и нужна
очередь (`collections.deque`), а не стек.

## Что нужно знать про операции

В Python стек — это обычный `list`, у которого используется только правый конец.

| Операция | Код | Сложность |
|---|---|---|
| положить | `stack.append(x)` | O(1) амортизированно |
| снять | `stack.pop()` | O(1) |
| посмотреть вершину | `stack[-1]` | O(1) |
| пуст ли | `not stack` | O(1) |

`pop()` и `stack[-1]` на пустом списке бросают `IndexError`, поэтому проверка
`if stack` перед ними — обязательная привычка.

Не используйте `list.pop(0)` и `list.insert(0, x)`: они сдвигают весь массив,
это O(n). Если нужны оба конца — берите `collections.deque`.

## Четыре приёма

### 1. Matching pairs (парные элементы)

Стек хранит всё, что ещё **не нашло пару**. Новый элемент сравнивается только
с вершиной: либо они образуют пару и вершина снимается, либо элемент ложится
сверху.

```python
stack = []
for item in data:
    if stack and образуют_пару(stack[-1], item):
        stack.pop()
    else:
        stack.append(item)
# что осталось в стеке — осталось без пары
```

Когда: скобки, удаление соседних дубликатов, столкновения астероидов, теги.

### 2. Monotonic stack (монотонный стек)

В стеке лежат элементы, **ожидающие ответа**, и их значения упорядочены —
например, не возрастают от дна к вершине. Порядок поддерживается сам собой:
перед тем как положить новый элемент, снимаем всех, кого он «побеждает».
Для снятых он и есть ответ.

```text
значения в стеке:   9  6  6  2        пришло 7
                             ^ вершина

снимаем 2, 6, 6  (все меньше 7)  → для них ответ 7
стек:               9  7              9 ≥ 7, остановились
```

```python
answer = [-1] * len(nums)
stack = []                                  # индексы, а не значения
for i, value in enumerate(nums):
    while stack and nums[stack[-1]] < value:
        answer[stack.pop()] = value
    stack.append(i)
```

Внутри `for` стоит `while`, но это O(n): каждый индекс кладётся один раз
и снимается не больше одного раза.

Какой знак ставить в `while`:

| Ищем | Снимаем, пока вершина | Стек от дна к вершине |
|---|---|---|
| следующий **больший** | `<` нового | не возрастает |
| следующий **больший или равный** | `<=` нового | строго убывает |
| следующий **меньший** | `>` нового | не убывает |

**Monotonic deque (монотонный дек)** — тот же приём для скользящего окна.
У стека открывается второй конец: справа по-прежнему снимаем побеждённых,
слева выбрасываем тех, кто выехал за границу окна.

### 3. Nested context (сохранение контекста вложенности)

Встретив начало вложенной части, кладём в стек **всё, что знаем про внешний
уровень**, и начинаем считать внутренний с чистого листа. В конце вложенной
части достаём внешний контекст и вливаем в него результат.

```python
saved = []
state = начальное_состояние()
for token in tokens:
    if token открывает уровень:
        saved.append(state)
        state = начальное_состояние()
    elif token закрывает уровень:
        state = объединить(saved.pop(), state)
    else:
        state = обновить(state, token)
```

Это ручная имитация рекурсии: стек вызовов хранит ровно то же самое.

Когда: калькуляторы, раскодирование строк вида `3[ab2[c]]`, упрощение путей.

### 4. Two stacks (два стека)

Перекладывание из одного стека в другой **разворачивает порядок**. Два
разворота возвращают исходный порядок — так из двух LIFO получается FIFO.

```text
enqueue 1, 2, 3        inbox: [1 2 3]   outbox: []
                                   ^ вершина
перекладываем          inbox: []        outbox: [3 2 1]
                                                     ^ вершина — самый старый
```

Когда: очередь на стеках, стек с минимумом за O(1), «отменить / вернуть».

### Правильная скобочная последовательность

**Условие.** Строка состоит из скобок трёх видов: `()`, `[]`, `{}`. Проверить,
что каждая открывающая закрыта скобкой своего вида и пары не пересекаются:
`([])` — можно, `([)]` — нельзя. Пустая строка корректна.

**Почему не хватит счётчиков.** Поровну открывающих и закрывающих каждого
вида — условие необходимое, но не достаточное: в `())(` и в `[(])` счётчики
сходятся. Важен порядок, а его счётчик не помнит.

**Идея.** Закрывающая скобка всегда относится к **последней незакрытой**
открывающей: всё, что открыто внутри пары, обязано закончиться раньше самой
пары. «Последняя незакрытая» — это вершина стека. Открывающую кладём,
на закрывающей снимаем вершину и сверяем вид.

Отказов три, и забыть легко любой:

1. закрывающая пришла, а стек пуст — `)`;
2. вид вершины не совпал — `(]`;
3. строка кончилась, а стек не пуст — `((`.

```text
text = "{[(])}"

{   кладём           стек: {
[   кладём           стек: { [
(   кладём           стек: { [ (
]   на вершине (     ждали ), пришла ]  → False
```

Если бы виды совпали на всех шагах и стек в конце опустел — ответ `True`.

### Ближайшее большее число справа

**Условие.** Для каждого `nums[i]` найти первое число правее, которое строго
больше него. Если такого нет — `-1`.

**Идея.** Идём слева направо и держим в стеке индексы чисел, которые ответа
**ещё не дождались**. Новое число `x` — ответ для всех ждущих, кто меньше `x`:
оно правее них и первое такое, иначе они ушли бы из стека раньше.

**Почему достаточно смотреть на вершину.** Значения в стеке не возрастают от
дна к вершине: элемент кладётся только после того, как сняты все меньшие.
Значит, если вершина не меньше `x`, то и всё под ней не меньше `x` — копать
глубже незачем.

**Почему O(n).** Каждый индекс кладётся один раз и снимается не больше раза:
не более 2n операций со стеком на весь проход.

```text
nums = [3, 8, 4, 1, 7, 9]

x = 3   снять некого        стек: 3
x = 8   снимаем 3 → 8       стек: 8
x = 4   8 ≥ 4               стек: 8 4
x = 1   4 ≥ 1               стек: 8 4 1
x = 7   снимаем 1, 4 → 7    стек: 8 7
x = 9   снимаем 7, 8 → 9    стек: 9
конец   у 9 ответа нет      → -1

ответ: [8, 9, 7, 7, 9, -1]
```

(В стеке лежат индексы; значения показаны для наглядности.)

**Другой вариант.** Можно идти справа налево и держать в стеке **кандидатов**
в ответ: снимаем всех, кто не больше текущего числа, — ответом будет
оставшаяся вершина. Сложность та же; выбирайте тот вариант, который вам
проще объяснить.

### Вычислить выражение со скобками

**Условие.** Строка содержит неотрицательные целые числа, `+`, `-`, круглые
скобки и пробелы; выражение корректно. Вернуть его значение, не пользуясь
`eval`. Минус может быть унарным: `-5 + 2`, `-(4 - 9)`, `3 - -2`.

**Шаг 1: без скобок.** Вычитание — это сложение с числом другого знака, так
что выражение — просто сумма слагаемых со знаками. Держим три переменные:
`total` — сумма завершённых слагаемых, `sign` — знак текущего, `number` —
текущее число, которое собирается по цифрам (`number * 10 + цифра`). Оператор
означает «слагаемое закончилось»: вливаем `sign * number` в `total`
и запоминаем новый знак.

**Шаг 2: скобки.** Содержимое скобок — такое же выражение, его можно считать
теми же тремя переменными с нуля. Нужно лишь не потерять внешний уровень:
на `(` кладём в стек пару `(total, sign)` — недосчитанную внешнюю сумму и знак
перед скобкой. На `)` достаём пару обратно, а значение скобки записываем
в `number`: для внешнего уровня скобка — это обычное слагаемое, и дальше оно
обрабатывается общим правилом.

**Шаг 3: унарный минус.** Знак унарный, если слагаемое ещё не началось:
в начале строки, после оператора, после `(`. Такой знак ничего не завершает,
он лишь переворачивает `sign`. Для этого хватает одного флага
`operand_expected`.

```text
expression = "25 - (6 + (11 - 3)) + 4"

символ   total  sign  number   стек
25          0    +       25    —
-          25    -        0    —
(           0    +        0    (25,-)
6           0    +        6    (25,-)
+           6    +        0    (25,-)
(           0    +        0    (25,-) (6,+)
11          0    +       11    (25,-) (6,+)
-          11    -        0    (25,-) (6,+)
3          11    -        3    (25,-) (6,+)
)           6    +        8    (25,-)          скобка = 11 - 3 = 8
)          25    -       14    —               скобка = 6 + 8 = 14
+          11    +        0    —               25 - 14 = 11
4          11    +        4    —
конец      11 + 4 = 15
```

**Сложность.** Один проход — O(n). В стеке по одной записи на каждую ещё
не закрытую скобку — O(d), где d — глубина вложенности.

### Удаление соседних дубликатов

**Условие.** Пока в строке есть две одинаковые буквы подряд, удаляем такую
пару. Вернуть то, что останется. Удаляется именно пара: из `aaa` получится `a`.

**Наивно.** Искать пару, вырезать, начинать сначала — O(n²): строка вида
`abcd…dcba` схлопывается по одной паре за проход.

**Идея.** Стек — это уже очищенный префикс строки. Новая буква либо совпадает
с вершиной и пара исчезает, либо ложится сверху. После исчезновения пары
вершиной становится буква, лежавшая под ней, — именно она оказалась бы
соседом следующей буквы в настоящей строке. Цепная реакция получается сама.

**Почему порядок удалений не важен.** Результат не зависит от того, какую
пару убирать первой, поэтому жадное удаление
«как только увидели» даёт тот же ответ, что и любой другой порядок.

```text
text = "kayyakpop"

k   кладём             стек: k
a   кладём             стек: k a
y   кладём             стек: k a y
y   совпал с вершиной  стек: k a
a   совпал с вершиной  стек: k
k   совпал с вершиной  стек: (пусто)
p   кладём             стек: p
o   кладём             стек: p o
p   кладём             стек: p o p

ответ: "pop"
```

В конце `"".join(stack)` — стек уже хранит буквы в нужном порядке.

### Очередь на двух стеках

**Условие.** Реализовать очередь с операциями `enqueue`, `dequeue`, `peek`,
`is_empty`, используя только стеки, то есть только `append` и `pop` с одного
конца.

**Идея.** `inbox` принимает новые элементы, `outbox` отдаёт. Когда `outbox`
пуст, а элемент нужен, перекладываем в него **весь** `inbox`: порядок
разворачивается, и самый старый элемент оказывается на вершине.

**Главное правило: перекладывать только в пустой `outbox`.** Если досыпать
в непустой, свежие элементы лягут поверх старых и выйдут раньше них.

```text
enqueue a, b        inbox: a b      outbox: —
dequeue → a         inbox: —        outbox: b        переложили, сняли a
enqueue c           inbox: c        outbox: b        c ждёт своей очереди
dequeue → b         inbox: c        outbox: —        перекладывать не пришлось
dequeue → c         inbox: —        outbox: —        переложили, сняли c
```

**Почему амортизированно O(1).** Отдельный `dequeue` может стоить O(n) — когда
приходится перекладывать n элементов. Но посмотрим на судьбу одного элемента:
его один раз кладут в `inbox`, один раз перекладывают в `outbox` и один раз
оттуда снимают. Три действия на элемент, и обратно в `inbox` он не возвращается
никогда. Значит, любые m операций над очередью стоят не больше 3m действий
в сумме — в среднем O(1) на операцию.

Удобная метафора — предоплата: каждый `enqueue` платит три монеты — одну
тратит сразу, две оставляет «на элементе». Этими монетами потом оплачиваются
его перекладывание и снятие, поэтому дорогой `dequeue` уже оплачен заранее.

«Амортизированно» не значит «в среднем по случайным данным»: это гарантия
на **любую** последовательность операций, просто выданная на сумму, а не
на каждый вызов.

### Максимумы скользящего окна

**Условие.** Дан массив и размер окна `k`. Окно едет слева направо по одному
шагу; вернуть максимум в каждом положении. Если `k` больше длины массива —
окон нет, ответ пустой.

**Наивно.** `max` по каждому окну — O(n·k).

**Ключевое наблюдение.** Пусть в окне есть числа `a` и правее него `b ≥ a`.
Тогда `a` максимумом уже не будет никогда: пока `a` в окне, в нём и `b`,
ведь `b` уедет позже. Таких «безнадёжных» можно выбрасывать сразу.

**Идея.** Дек индексов, значения в котором строго убывают слева направо.

1. Новое число снимает с **правого** конца всех, кто не больше него, и встаёт
   в конец.
2. Если индекс на **левом** конце выехал из окна (`≤ right - k`), убираем его.
   Выехать мог только он: индексы в деке возрастают.
3. Максимум окна — на левом конце.

Храним **индексы**, а не значения: иначе не понять, выехал ли элемент из окна.

```text
nums = [4, 2, 7, 1, 3, 6, 5], k = 3

right  x   действие                         дек (значения)   максимум
0      4   кладём                           4                —
1      2   кладём                           4 2              —
2      7   снимаем 2, 4; кладём             7                7
3      1   кладём                           7 1              7
4      3   снимаем 1; кладём                7 3              7
5      6   снимаем 3; 7 выехал из окна      6                6
6      5   кладём                           6 5              6

ответ: [7, 7, 7, 6, 6]
```

**Сложность.** Каждый индекс входит в дек один раз и выходит не больше раза —
O(n). В деке только индексы текущего окна — O(k) памяти.

**Почему не куча.** Куча с ленивым удалением тоже решает задачу, но за
O(n log n). Монотонный дек пользуется тем, что окно едет только вправо.

## Типичные ошибки

- **`pop()` или `stack[-1]` без проверки на пустоту.** В скобках это строка `)`,
  в очереди — `dequeue` из пустой. Проверка `if stack` идёт **первой** в условии:
  `while stack and ...`.
- **Забытая проверка в конце.** `((` проходит весь цикл без единой ошибки;
  ответ — `not stack`, а не `True`.
- **Значения вместо индексов в монотонном стеке.** Значениями ответ
  не записать: непонятно, в какую ячейку. В окне без индексов не узнать,
  что элемент устарел.
- **`<` и `<=` перепутаны.** В «следующем большем» равные числа должны
  оставаться в стеке (`[5, 5]` → `[-1, -1]`). В окне, наоборот, равных лучше
  снимать — более свежий дубликат проживёт дольше.
- **«Вложенный цикл — значит O(n²)».** Считайте не итерации, а операции
  со стеком: каждый элемент кладётся и снимается по одному разу.
- **Калькулятор: потерянное последнее число.** После цикла в `number` остаётся
  незавершённое слагаемое — нужен финальный `total + sign * number`.
- **Калькулятор: число по одной цифре.** `"120"` — одно число, а не три;
  собирайте его как `number * 10 + digit`.
- **Калькулятор: в стек кладут только сумму, без знака.** Тогда `5 - (2 + 1)`
  превращается в `5 + 3`.
- **Очередь: перекладывание в непустой `outbox`** или перекладывание туда
  и обратно на каждой операции — первое ломает порядок, второе даёт O(n)
  на операцию.
- **`list.pop(0)` в роли очереди.** Это O(n); для двусторонних операций есть
  `collections.deque`.
