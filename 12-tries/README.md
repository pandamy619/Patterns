# 12. Tries (префиксные деревья)

## Суть в двух предложениях

Trie — это дерево, в котором каждое ребро подписано символом, а путь от корня
до узла читается как строка; слова с общим началом идут по общему пути, и это
начало хранится один раз. Благодаря этому вопросы «есть ли такое слово?» и
«есть ли слова с таким началом?» решаются за время, равное **длине запроса**,
сколько бы слов ни лежало в структуре.

Главное, что trie умеет и чего не умеет хеш-множество, — отвечать про
**незаконченную** строку. Множество знает только целые ключи: пока слово не
дописано, спрашивать его не о чем. А в trie можно стоять в узле, дописывать по
букве и после каждой знать, есть ли смысл продолжать.

## Как узнать паттерн

- в условии звучит слово **«префикс»**: автодополнение, «начинается с»,
  самый длинный общий префикс, поиск по первым буквам;
- есть **словарь из многих слов**, и с ним сверяется что-то, что строится
  **по одной букве**: путь по клеткам, перебор с возвратом, поток символов;
- в запросе есть **подстановочные символы**, и подходящее слово нужно искать,
  не перебирая весь словарь;
- слов много, и у них **много общих начал** (URL, пути к файлам, телефонные
  номера, IP-адреса в двоичном виде);
- наивное решение — «для каждого запроса пройти по всем словам и сравнить».

Контрпример: нужна только проверка «слово целиком есть / нет», без префиксов
и шаблонов. Здесь хватит `set`: он проще, в разы компактнее и на практике
быстрее (см. тему 02 и сравнение ниже). Trie без вопросов про префиксы — это
лишняя сложность.

## Что нужно знать про trie

**Устройство.** Узел хранит две вещи: переходы к потомкам (символ → узел) и
отметку «здесь кончается слово». Сам символ в узле не записан — он живёт на
ребре, то есть служит ключом в словаре родителя. Корень соответствует пустой
строке.

```text
слова: sun, sung, sky, so            * — отметка конца слова

(root)
└─ s
   ├─ k
   │  └─ y*
   ├─ o*
   └─ u
      └─ n*          ← «sun» — слово и одновременно префикс «sung»
         └─ g*
```

Четыре слова, 12 букв, а узлов с буквами всего 7: общая `s` и общее `sun`
хранятся один раз. Отметка нужна потому, что путь есть у любого префикса:
`su` в дереве «присутствует», но словом не является.

```python
class TrieNode:
    __slots__ = ("children", "is_word")

    def __init__(self) -> None:
        self.children: dict[str, TrieNode] = {}
        self.is_word = False
```

**Сложность — через длину слова.** Пусть L — длина слова или префикса,
N — число слов, W — суммарная длина всех слов, A — размер алфавита.

| Операция | Время | Почему |
|---|---|---|
| вставка | O(L) | один шаг вниз на символ, новых узлов не больше L |
| поиск слова | O(L) | спуск и проверка отметки |
| проверка префикса | O(L) | спуск; отметка не важна |
| все слова с префиксом | O(L + размер поддерева) | спуск, затем обход вниз |
| поиск с k точками | до O(min(A^k · L, число узлов)) | на каждой точке ветвимся |

От N время не зависит вообще — в этом смысл структуры. Честное замечание:
у хеш-множества поиск строки тоже O(L), а не O(1), — строку надо захешировать
и при совпадении хеша сравнить. Асимптотика одинаковая, разница в другом:
множество читает L байт подряд, а trie делает L переходов по ссылкам в разные
места памяти, и константа у него заметно хуже.

**Оценка памяти.** В худшем случае общих префиксов нет, и на каждый символ
каждого слова приходится свой узел: **O(W)** узлов. Сверху число узлов
ограничено ещё и формой дерева: на глубине d их не больше A^d. В лучшем
случае (одно слово — префикс остальных) узлов столько, сколько букв в самом
длинном слове.

Но «узел» — это не байт. Замер на CPython 3.11: 50 000 искусственных слов из
слогов, длиной 4–10 букв, в сумме 475 тысяч символов.

```text
узлов в trie             100 155    (в 4,7 раза меньше, чем символов, — префиксы сжались)
память trie             ≈ 18,8 МБ   (≈ 190 байт на узел: объект 48 + его dict)
память set тех же слов  ≈  5,0 МБ   (≈ 100 байт на слово)
```

Вывод: trie экономит **число хранимых символов**, но не
обязательно байты — каждый символ превращается в объект со словарём внутри.
Компактнее хеш-множества он становится, только когда префиксы перекрываются
очень сильно или когда узел устроен экономно (сжатые цепочки — radix tree,
узлы в массивах).

**`dict` или массив на 26 ячеек.** Массив даёт переход по индексу
`ord(ch) - ord('a')` без хеширования, но каждый узел платит за все 26 ячеек
(в CPython список на 26 ссылок — 264 байта, в C или Java — 208 байт одних
указателей), даже если потомок один. `dict` хранит только существующие рёбра
и не привязан к латинице. В Python разумный выбор по умолчанию — `dict`.

**Когда trie лучше хеш-множества.**

| Нужно | `set` | trie |
|---|---|---|
| слово целиком есть / нет | O(L), просто и компактно — **берите его** | O(L), но медленнее и прожорливее |
| есть ли слова с префиксом | перебор всех слов O(N·L) либо множество всех префиксов — O(L²) символов на слово | O(L) |
| проверять префикс, **дописывая по букве** | каждый раз хешировать всю строку заново: O(L) на шаг, O(L²) на слово | O(1) на шаг: держим ссылку на узел и делаем один переход |
| шаблон с точками | перебор всех слов | обход только подходящих ветвей |
| выдать слова по алфавиту, автодополнение | сортировка | обход поддерева по отсортированным рёбрам |
| самый длинный префикс строки, который есть в словаре | L запросов по O(L) | один спуск |

## Три приёма

### 1. Prefix walk (спуск по префиксу)

Основа всего: идём от корня, на каждом символе делаем один переход. Вставка
создаёт недостающие узлы, поиск на первом же отсутствующем ребре сдаётся.

```python
def walk(root, text):
    node = root
    for letter in text:
        node = node.children.get(letter)
        if node is None:
            return None          # пути нет — нет ни слова, ни префикса
    return node

# search:      node is not None and node.is_word
# has_prefix:  node is not None
```

Когда: словарь со вставкой и поиском, автодополнение, самый длинный общий
префикс, подсчёт слов с данным началом (в узле держим счётчик).

### 2. Branching DFS (ветвление на подстановочном символе)

Пока символ запроса известен, путь единственный. Как только символ может быть
любым — пробуем **всех** потомков текущего узла; достаточно, чтобы повезло
хотя бы одной ветви.

```text
запрос «l.ne»        (root) ─ l ─┬─ a ─ m ─ p*     «.» = a → нужно n, ребра нет  ✗
                                 └─ i ─┬─ m ─ e*
                                       └─ n ─ e*   «.» = i → n → e*              ✓
```

```python
def matches(node, pattern, index):
    if index == len(pattern):
        return node.is_word
    symbol = pattern[index]
    if symbol == ".":
        return any(matches(child, pattern, index + 1)
                   for child in node.children.values())
    child = node.children.get(symbol)
    return child is not None and matches(child, pattern, index + 1)
```

Когда: шаблоны с «любым символом», поиск с допуском одной опечатки, подбор
слов по известным буквам.

### 3. Trie-guided backtracking (trie как проводник перебора)

Перебор строит строку по символу — и параллельно спускается по trie. Узел
trie становится частью состояния перебора: он за O(1) отвечает, может ли
текущая строка дорасти хотя бы до одного слова словаря. Нет ребра — ветку
бросаем, причём сразу **для всех слов**. Найденные слова снимаем с дерева,
а опустевшие ветви срезаем (pruning), чтобы не ходить по ним снова.

```python
def explore(cell, parent):
    node = parent.children[letter_at(cell)]   # ребро есть — проверено до вызова
    if node.is_word:
        запомнить_слово()
        node.is_word = False                  # второй раз не найдём
    пометить(cell)
    for nxt in соседи(cell):
        if letter_at(nxt) in node.children:   # trie решает, куда вообще идти
            explore(nxt, node)
    снять_пометку(cell)
    if not node.is_word and not node.children:
        del parent.children[letter_at(cell)]  # обрезка опустевшей ветви
```

Когда: много слов на одном поле, разбиение строки на слова из словаря,
T9 и похожие задачи, где кандидаты растут посимвольно.

### Префиксное дерево

**Условие.** Реализовать структуру с тремя операциями: `insert(word)` —
добавить слово, `search(word)` — есть ли ровно такое слово,
`has_prefix(prefix)` — есть ли хоть одно слово с таким началом.

**Идея.** Все три операции — один и тот же спуск от корня, различается только
финал. `insert` по дороге создаёт недостающие узлы и ставит отметку на
последнем. `search` требует, чтобы путь существовал **и** заканчивался
отметкой. `has_prefix` довольствуется тем, что путь существует. Общий спуск
вынесен в `_walk`, поэтому `search` и `has_prefix` — по две строки.

**Почему `has_prefix` не смотрит на отметки.** Узлы создаёт только `insert`,
и каждый созданный узел лежит на пути к слову, которое эта вставка добавила.
Удаления нет, значит под любым узлом (кроме корня) всегда есть хотя бы одно
слово. Корень — единственное исключение: он существует и в пустом дереве,
поэтому для пустого префикса решение дополнительно проверяет, что в дереве
вообще что-то лежит.

**Сложность.** Каждая операция делает по одному переходу на символ: O(L)
и никакой зависимости от числа слов. Память — O(W) в худшем случае.

```text
операция            путь от корня                 результат
insert("sung")      s → u → n → g, отметка на g
insert("sky")       s (уже есть) → k → y, отметка на y
has_prefix("su")    s → u: путь есть               True
search("sun")       s → u → n: отметки нет         False   ← префикс, но не слово
insert("sun")       новых узлов нет, отметка на n
search("sun")       s → u → n: отметка есть        True
search("sunga")     s → u → n → g → нет ребра «a»  False
has_prefix("sko")   s → k → нет ребра «o»          False
```

### Словарь с поиском по шаблону с точками

**Условие.** Две операции: `insert(word)` — добавить слово из букв;
`search(pattern)` — есть ли слово, подходящее под шаблон, где точка заменяет
**ровно одну** любую букву. Шаблон без точек — обычный поиск слова.

**Идея.** Вставка — как в обычном trie. Поиск — обход в глубину: по букве идём
по единственному ребру, на точке перебираем всех потомков и продолжаем шаблон
со следующей позиции из каждого. Ответ «да», если хоть одна ветвь дошла до
конца шаблона и остановилась на отметке. В решении буквы проходятся циклом,
а рекурсивный вызов делается только на точке, так что глубина стека равна
числу точек, а не длине шаблона.

**Почему корректно.** Точка — это «любое ребро», а все рёбра узла перед нами
в `children`. Перебрав их, мы рассматриваем все слова, совпадающие с шаблоном
на уже пройденной части, и только их. Длина совпадает автоматически: каждый
символ шаблона — ровно один шаг вниз, а отметка проверяется только после
последнего.

**Сложность.** Без точек — O(L). Каждая точка умножает число живых ветвей
максимум на A, но ветвей не может быть больше, чем узлов в дереве на этой
глубине. Худший случай — шаблон из одних точек: обойдём все узлы первых L
уровней, O(min(A^L, число узлов)). Это всё равно не хуже перебора словаря,
а обычно намного лучше: буквы шаблона отсекают ветви целиком.

```text
слова: lamp, lime, line

(root)
└─ l
   ├─ a
   │  └─ m
   │     └─ p*
   └─ i
      ├─ m
      │  └─ e*
      └─ n
         └─ e*

search("l.ne")
  'l'  → узел l
  '.'  → пробуем потомков l: a, i
         a: 'n' → у «la» нет ребра n            → False, возвращаемся
         i: 'n' → узел lin, 'e' → узел line*    → True

search("la.e")
  'l' → 'a' → '.': единственный потомок m → 'e': у «lam» нет ребра e → False

search("li.")   → после точки стоим в «lim», затем в «lin» — отметок нет → False
search("....")  → первая же ветвь l → a → m → p* кончается отметкой      → True
```

### Все слова из списка на клеточном поле

**Условие.** Дано поле из букв и список слов. Вернуть те слова, которые можно
прочитать на поле, переходя между соседними **по стороне** клетками. В одном
слове клетку нельзя использовать дважды. Каждое слово входит в ответ один
раз, даже если читается несколькими способами.

**Наивно.** Для каждого слова запускать отдельный поиск в глубину из каждой
клетки: O(N · R·C · 3^L). Слова с общим началом («pea», «pear») заставляют
проходить одни и те же клетки заново.

**Идея.** Кладём все слова в один trie и обходим поле **один раз**. Из каждой
клетки запускаем DFS, который шагает по полю и синхронно спускается по trie:
шаг в соседнюю клетку разрешён, только если у текущего узла есть ребро с её
буквой. Так одна ветка перебора обслуживает сразу все слова с этим префиксом,
а тупиковые начала отбрасываются на первой же лишней букве. Узел с отметкой —
слово найдено; сами буквы слова копятся в списке `path`, который растёт и
укорачивается вместе с рекурсией.

Три детали, на которых держится решение:

- **Клетка не используется дважды.** На входе в клетку её буква заменяется
  пустой строкой, на выходе возвращается. Отдельная проверка «посещена ли» не
  нужна: ребра с пустой строкой в trie нет, и помеченная клетка отсеивается
  тем же условием, что и любая неподходящая буква.
- **Слово попадает в ответ один раз.** Нашли — сняли отметку `is_word`. Второй
  путь к тому же слову придёт в узел без отметки. Множество для ответа не нужно.
- **Обрезка (pruning).** На выходе из рекурсии: если у узла нет ни отметки,
  ни потомков, он больше не ведёт ни к одному ненайденному слову — удаляем
  ребро к нему у родителя. Цепочка схлопывается снизу вверх сама, потому что
  родитель выполняет ту же проверку на своём выходе. Когда дерево опустело
  целиком, обход поля прекращается досрочно.

**Почему обрезка ничего не ломает.** Удаляется только узел, под которым не
осталось отмеченных слов. Любой обход, который зашёл бы в него позже, заведомо
ничего не добавил бы в ответ. Значит, ответ тот же — меняется только объём
работы. В тестах это проверяется напрямую: `search_board(..., prune=False)`
обязан выдавать те же слова.

**Сложность.** Построение trie — O(W). Из каждой из R·C клеток DFS уходит
на глубину не больше L; на первом шаге 4 направления, дальше не больше 3
(назад нельзя): O(R·C·3^L) в худшем случае. На практике trie режет перебор
на порядки — оценка достигается только на полях из одинаковых букв. Память:
O(W) на trie и O(L) на рекурсию и `path`.

```text
поле:   p e a r       слова: pear, pea, pep, plus, lint, line, ant, son, eon
        l i n t
        u s o e

trie до обхода — 23 узла             trie после обхода — 8 узлов

(root)                               (root)
├─ a                                 ├─ l
│  └─ n                              │  └─ i
│     └─ t*                          │     └─ n
├─ e                                 │        └─ e*
│  └─ o                              └─ p
│     └─ n*                             └─ e
├─ l                                       └─ p*
│  └─ i
│     └─ n
│        ├─ e*
│        └─ t*
├─ p
│  ├─ e
│  │  ├─ a*
│  │  │  └─ r*
│  │  └─ p*
│  └─ l
│     └─ u
│        └─ s*
└─ s
   └─ o
      └─ n*

старт из (0,0) 'p'   — ребро root→p есть
  вниз (1,0) 'l'     → p-l → (2,0) 'u' → (2,1) 's'*   найдено «plus», отметка снята
                       на выходе срезаны s, потом u, потом l — ветки «pl…» больше нет
  вправо (0,1) 'e'   → p-e
    вниз 'i'         — ребра нет; влево 'p' — клетка помечена, ребра "" нет
    вправо (0,2) 'a'*  найдено «pea»
      вправо (0,3) 'r'*  найдено «pear»; на выходе срезаны r, потом a
  узел p-e остаётся: под ним ещё живёт «pep» (вторая 'p' занята — слово не нашлось)

ответ в порядке обнаружения: plus, pea, pear, ant, lint, son, eon
не найдены: «pep» (нужна одна и та же клетка дважды), «line» (рядом с n нет e)
```

Насколько обрезка экономит работу, зависит от поля. На примере выше вызовов
DFS 21 и с обрезкой, и без неё — повторно ходить по найденным веткам просто
некому. А вот поле 4×4 из одних букв `a`:

```text
слова                    вызовов DFS с обрезкой    без обрезки
["aaaaaa"]                         6                  1632
["aaaaaa", "aaaaab"]             833                  1632
```

В первой строке слово находится первым же спуском, дерево пустеет, и обход
останавливается. Во второй — ненайденное «aaaaab» удерживает почти всю ветку,
и срезать удаётся только половину работы.

## Типичные ошибки

- **`search` без проверки отметки.** Дошли до узла — ещё не значит, что слово
  есть: так «su» «найдётся» в дереве со словом «sun». Это отличие `search`
  от `has_prefix`, и больше между ними отличий нет.
- **Отметку конца слова ставят в цикле, а не после него** — все префиксы
  вставленного слова становятся словами.
- **Хранить символ в узле и искать потомка перебором.** Переход должен быть
  O(1): символ — ключ словаря (или индекс массива), а не поле потомка.
- **Точка как «ноль или больше букв».** В этой задаче точка — ровно одна
  буква; шаблон `li.` не подходит ни к `li`, ни к `lime`.
- **Вернуть результат первой ветви на точке.** `return matches(first_child)`
  вместо `any(...)`: если первая ветвь тупиковая, остальные не проверяются.
- **Забыли снять пометку с клетки при откате.** Клетка остаётся занятой для
  всех следующих путей; на маленьких примерах это часто не видно.
- **Дубликаты в ответе.** Слово читается двумя путями — и попадает в список
  дважды. Лечится снятием отметки, а не `set` вокруг ответа.
- **Обрезка до обхода соседей.** Срезать узел можно только на выходе из
  рекурсии: на входе ещё неизвестно, найдутся ли слова под ним.
- **Отдельный DFS на каждое слово.** Рабочее, но наивное решение:
  оно не использует общие префиксы слов.
- **«Trie экономит память» без оговорок.** Экономит узлы, но не байты —
  см. замер выше.
