# 09. Intervals (интервалы)

## Суть в двух предложениях

Интервал — это пара чисел `[start, end]`: встреча в календаре, бронь, отрезок
на числовой прямой. Пока интервалы лежат как попало, любой вопрос про них требует
сравнить каждый с каждым за O(n²); стоит **упорядочить их по началу** (или
разобрать на отдельные события «открылся» и «закрылся») — и на тот же вопрос
отвечает один проход слева направо.

Сортировка даёт главное: когда мы дошли до интервала, всё, что началось раньше,
уже обработано, а всё, что начнётся позже, ещё впереди. Поэтому сравнивать
текущий интервал приходится не со всеми, а с одним-двумя «ближайшими».

## Как узнать паттерн

- вход — список пар `[start, end]`: встречи, смены, брони, диапазоны адресов, отрезки;
- в условии звучит **«пересекаются», «накладываются», «одновременно», «свободное окно»**;
- нужно **слить**, **вычесть**, **пересечь** наборы интервалов или **вставить** новый;
- спрашивают про **максимальную загрузку**: сколько переговорок, платформ, серверов
  нужно в пиковый момент;
- наивное решение — сравнить каждый интервал с каждым;
- порядок интервалов во входе не важен, то есть сортировка ничего не ломает.

Контрпример: интервалы фиксированы, а вопросов много и они приходят по одному —
«какие интервалы содержат точку x?», «добавь интервал и сразу скажи пиковую
загрузку». Пересортировывать и заново проходить список на каждый запрос — это O(n)
или O(n log n) на запрос. Тут нужны бинарный поиск по заранее слитым интервалам,
упорядоченный словарь или дерево интервалов (interval tree).

## Что нужно знать про интервалы

### Когда два интервала пересекаются

Проще сформулировать обратное: интервалы **не** пересекаются, когда один целиком
левее другого — `a.end < b.start` или `b.end < a.start`. Отрицание этого и есть
условие пересечения (для закрытых интервалов):

```python
a.start <= b.end and b.start <= a.end
```

Если известно, что `a` начинается не позже `b` (а после сортировки это известно
всегда), вторая половина условия выполнена автоматически и остаётся одно сравнение:

```python
b.start <= a.end
```

```text
a.start <= b.start

 не пересекаются            пересекаются               b внутри a
 a |------|                 a |--------|               a |------------|
 b           |-----|        b       |------|           b     |----|
   a.end < b.start            b.start <= a.end           b.start <= a.end
```

Когда пересечение есть, обе производные величины считаются одинаково просто:

```python
пересечение = [max(a.start, b.start), min(a.end, b.end)]
объединение = [min(a.start, b.start), max(a.end, b.end)]
```

Формулу пересечения можно применять и вслепую: если получилось `lo > hi`,
значит, общей части нет.

### Зачем сортировать по началу

Без порядка кандидатом на пересечение с интервалом `x` может оказаться кто
угодно. После сортировки по началу все «опасные» для `x` интервалы стоят слева
от него, и среди них важен только тот, чей конец правее всех. Вместо n сравнений —
одно. Сортировка стоит O(n log n), и почти всегда именно она определяет итоговую
сложность: сам проход линейный.

Сортировать по концу тоже бывает нужно — например, в жадной задаче «выбрать
максимум непересекающихся интервалов». Но для слияния и подсчёта пересечений
нужен порядок именно по началу.

### Закрытые и полуоткрытые интервалы

Это первое, что стоит уточнить в условии: **входит ли конец в интервал?**

| | Закрытый `[start, end]` | Полуоткрытый `[start, end)` |
|---|---|---|
| Точка `end` | принадлежит интервалу | не принадлежит |
| `[1, 3]` и `[3, 5]` | пересекаются (общая точка 3) | не пересекаются |
| Условие пересечения, `a` левее | `b.start <= a.end` | `b.start < a.end` |
| Пересечение пусто, когда | `lo > hi` | `lo >= hi` |
| В одной точке сначала обрабатываем | открытия | закрытия |
| Типичный смысл | отрезки на прямой, диапазоны номеров | время: встреча 10:00–11:00 и встреча 11:00–12:00 идут в одной комнате |

Вся разница — в одном знаке (`<=` против `<`) и в порядке событий с одинаковой
координатой, но ответ от этого меняется. Соглашения в этой теме:

- **Слияние** и **пересечения двух списков** — интервалы **закрытые**:
  касание в одной точке считается пересечением.
- **Наибольшее перекрытие** — интервалы **полуоткрытые**: конец не входит,
  и `[1, 3)` с `[3, 5)` одновременно активными не бывают.

В коде интервал — список из двух чисел `[start, end]`, набор интервалов —
`list[list[int]]`. Функции вход не изменяют.

## Три приёма

### 1. Sort and merge with last (сортировка по началу и слияние с последним)

Сортируем по началу и строим ответ слева направо. Очередной интервал сравниваем
только с **последним интервалом ответа**: либо он его продлевает, либо начинает
новый кусок.

```text
вход после сортировки:        ответ растёт справа:

|-----|                       |-----|
   |--------|                 |-----------|        продлили
     |--|                     |-----------|        ничего не изменилось
                |----|        |-----------|  |----|   новый кусок
```

```python
result = []
for start, end in sorted(intervals):
    if result and start <= result[-1][1]:            # для [a, b) — строго <
        result[-1][1] = max(result[-1][1], end)
    else:
        result.append([start, end])
```

Когда: слить пересекающиеся интервалы, вставить интервал в отсортированный
список, найти свободные окна в расписании (это промежутки между кусками ответа).

### 2. Two pointers over two sorted lists (два указателя по двум отсортированным спискам)

Два списка уже упорядочены и внутри себя не пересекаются. Держим по указателю
на каждый, обрабатываем текущую пару и сдвигаем тот указатель, чей интервал
**раньше закончился**: он больше ни с кем пересечься не сможет.

```text
A:  |------|        |-----|
B:      |---------------|     |---|
    ^   ^
    i   j      A[i] кончился раньше → i += 1, а B[j] ещё пригодится
```

```python
i = j = 0
while i < len(a) and j < len(b):
    lo = max(a[i][0], b[j][0])
    hi = min(a[i][1], b[j][1])
    if lo <= hi:
        обработать(lo, hi)
    if a[i][1] < b[j][1]:
        i += 1
    else:
        j += 1
```

Когда: общее свободное время двух людей, пересечение двух расписаний, слияние
двух уже отсортированных списков интервалов. По сути это шаг слияния из
merge sort, только сравниваются концы.

### 3. Sweep line (заметающая прямая)

Забываем, что у интервала два конца, связанных между собой. Каждый интервал
превращается в два независимых **события**: `+1` в точке начала и `−1` в точке
конца. Сортируем события и ведём вертикальную прямую слева направо, поддерживая
счётчик активных интервалов.

```text
|-------------------|
      |-----|
            |-----------------|
+1    +1    -1+1    -1        -1     события
 1     2       2     1         0     счётчик после точки
```

```python
events = []
for start, end in intervals:
    events.append((start, +1))
    events.append((end, -1))
events.sort()          # при равной координате -1 окажется раньше +1

active = best = 0
for _, delta in events:
    active += delta
    best = max(best, active)
```

Порядок событий в одной точке — это и есть выбор между закрытыми и полуоткрытыми
интервалами. Для `[start, end)` закрытия идут первыми, и сортировка кортежей
`(точка, ±1)` даёт это бесплатно. Для закрытых интервалов первыми должны идти
открытия — тогда ключ сортировки `(точка, -delta)`.

Когда: пиковая загрузка, минимальное число переговорок или платформ, «сколько
пассажиров в машине», линия горизонта (skyline).

### Слить пересекающиеся интервалы

**Условие.** Дан список **закрытых** интервалов в произвольном порядке, у каждого
`start <= end`. Вернуть список попарно непересекающихся интервалов, покрывающий
те же точки. Касание считается пересечением: `[1, 4]` и `[4, 6]` дают `[1, 6]`.

**Идея.** Сортируем по началу и идём слева направо, сравнивая очередной интервал
с последним куском ответа. Начался не позже, чем тот кончился, — продлеваем
кусок; иначе открываем новый.

**Почему достаточно смотреть на последний кусок.** Куски ответа не пересекаются
и идут слева направо, значит, у последнего самый правый конец. Очередной интервал
начинается не раньше всех уже обработанных. Если он не достаёт до последнего
куска, то до предыдущих не достаёт тем более. А если достаёт — предыдущие
куски его всё равно не касаются: они кончаются левее начала последнего куска,
а новый интервал начинается не раньше этого начала.

**Почему `max`, а не просто `end`.** Интервал может лежать целиком внутри
текущего куска. Присваивание `result[-1][1] = end` в этом случае *укоротит* кусок,
и следующий интервал ошибочно окажется «отдельным».

**Сложность.** Сортировка O(n log n), проход O(n). Память O(n): отсортированная
копия и ответ.

```text
intervals = [[8, 10], [1, 3], [15, 16], [2, 6], [9, 12], [4, 5]]
sorted    = [[1, 3], [2, 6], [4, 5], [8, 10], [9, 12], [15, 16]]

[1, 3]     ответ пуст        → новый кусок   [[1, 3]]
[2, 6]     2 <= 3            → продлеваем    [[1, 6]]
[4, 5]     4 <= 6, max(6,5)  → без изменений [[1, 6]]
[8, 10]    8 >  6            → новый кусок   [[1, 6], [8, 10]]
[9, 12]    9 <= 10           → продлеваем    [[1, 6], [8, 12]]
[15, 16]   15 > 12           → новый кусок   [[1, 6], [8, 12], [15, 16]]
```

### Все пересечения двух списков

**Условие.** Даны два списка **закрытых** интервалов. Каждый отсортирован по
началу, и интервалы внутри одного списка не имеют общих точек. Вернуть все
непустые пересечения интервала из первого списка с интервалом из второго.
Пересечение может состоять из одной точки: `[1, 4]` и `[4, 9]` дают `[4, 4]`.

**Идея.** Пересекаться могут только интервалы из разных списков, поэтому идём
двумя указателями. Для текущей пары считаем `lo = max(начал)`, `hi = min(концов)`;
если `lo <= hi` — это пересечение. Дальше сдвигаем указатель того интервала,
который закончился раньше.

**Почему сдвигаем именно его.** Пусть `A[i]` кончается раньше, чем `B[j]`.
Все следующие интервалы второго списка начинаются строго правее конца `B[j]`,
то есть правее и конца `A[i]`, — с `A[i]` им не встретиться. А вот `B[j]` ещё
тянется вправо и может задеть `A[i + 1]`. Значит, `A[i]` можно отпустить, ничего
не потеряв, а `B[j]` отпускать рано. Если концы равны, следующий сосед каждого
начинается правее общего конца, так что безопасно сдвинуть любой из двух.

**Сложность.** Каждая итерация сдвигает один из указателей, поэтому итераций
не больше n + m. Дополнительной памяти, кроме ответа, нет. Перебор всех пар
дал бы O(n · m).

```text
first  = [[0, 3], [6, 8], [11, 15]]
second = [[2, 7], [8, 9], [12, 13], [14, 20]]

i=0 j=0   [0, 3]   и [2, 7]     lo=2  hi=3   ✓ [2, 3]     3 < 7    → i += 1
i=1 j=0   [6, 8]   и [2, 7]     lo=6  hi=7   ✓ [6, 7]     8 >= 7   → j += 1
i=1 j=1   [6, 8]   и [8, 9]     lo=8  hi=8   ✓ [8, 8]     8 < 9    → i += 1
i=2 j=1   [11, 15] и [8, 9]     lo=11 hi=9   —            15 >= 9  → j += 1
i=2 j=2   [11, 15] и [12, 13]   lo=12 hi=13  ✓ [12, 13]   15 >= 13 → j += 1
i=2 j=3   [11, 15] и [14, 20]   lo=14 hi=15  ✓ [14, 15]   15 < 20  → i += 1

ответ: [[2, 3], [6, 7], [8, 8], [12, 13], [14, 15]]
```

### Наибольшее перекрытие

**Условие.** Дан список **полуоткрытых** интервалов `[start, end)`, у каждого
`start < end`. Найти наибольшее число интервалов, активных в один и тот же
момент. Начало входит в интервал, конец — нет: `[1, 3)` и `[3, 5)` не
пересекаются, и ответ для них — 1. Для пустого списка ответ 0.

**Идея.** Разбираем интервалы на события `+1` (начало) и `−1` (конец), сортируем
и идём слева направо со счётчиком активных. Ответ — максимум счётчика.

**Почему в одной точке закрытия идут первыми.** Интервал `[1, 3)` в момент 3 уже
не активен, а `[3, 5)` — уже активен. Если сначала прибавить, а потом отнять,
счётчик на мгновение покажет 2, хотя такого момента не существует. В решении
события — кортежи `(точка, delta)`, где `delta` равна `-1` или `+1`; обычная
сортировка кортежей ставит `-1` перед `+1` сама.

**Почему счётчик не врёт.** После обработки всех событий в точке `p` счётчик
равен «сколько началось не позже `p`» минус «сколько закончилось не позже `p`» —
это в точности число интервалов с `start <= p < end`. Между событиями набор
активных не меняется, поэтому достаточно смотреть на счётчик только в событиях.
Промежуточные значения внутри одной точки максимум не завышают: сначала идут
вычитания, и счётчик растёт уже от честного минимума.

**Вариант без списка событий.** В файле есть вторая функция,
`largest_overlap_two_arrays`: начала и концы сортируются в два отдельных
массива, по началам идёт цикл, а указатель по концам «закрывает» всё, что
закончилось к этому моменту (`end <= start`). Какой именно интервал закрылся,
неважно — счётчику нужно только количество. Оценка та же, зато сразу видно,
что максимум всегда достигается в чьём-то начале.

**Сложность.** 2n событий, сортировка O(n log n), проход O(n), память O(n).

```text
intervals = [[1, 5], [2, 4], [4, 9], [3, 7], [7, 8]]

точка  событие  активных
  1      +1        1
  2      +1        2
  3      +1        3   ← максимум
  4      -1        2      сначала закрылся [2, 4) ...
  4      +1        3      ... и только потом открылся [4, 9)
  5      -1        2
  7      -1        1      то же самое: [3, 7) закрылся раньше,
  7      +1        2      чем открылся [7, 8)
  8      -1        1
  9      -1        0

ответ: 3
```

Будь интервалы закрытыми, в точке 4 одновременно жили бы `[1, 5]`, `[2, 4]`,
`[3, 7]` и `[4, 9]` — ответ стал бы 4. Один знак в условии меняет результат.

## Типичные ошибки

- **Не уточнить, входит ли конец.** `[1, 3]` и `[3, 5]` — пересечение или нет?
  От ответа зависит знак в сравнении и порядок событий; угадывать не нужно,
  нужно спросить.
- **`end` вместо `max(..., end)` при слиянии.** На вложенном интервале
  (`[1, 10]`, затем `[2, 3]`) кусок укорачивается, и ответ разваливается.
- **Забытая сортировка.** Слияние «с последним» по неотсортированному входу
  молча выдаёт неверный ответ.
- **Сортировка по концу там, где нужна по началу.** Для слияния это ломает
  инвариант «кандидат только один».
- **Сдвиг не того указателя.** В задаче о двух списках двигать надо интервал
  с меньшим *концом*, а не с меньшим началом. С началами решение проходит
  простые тесты и теряет пересечения, когда один длинный интервал накрывает
  нескольких соседей.
- **Открытия раньше закрытий в sweep line** для полуоткрытых интервалов:
  встречи 10–11 и 11–12 внезапно требуют две комнаты.
- **Правка входа.** `result.append(interval)` кладёт в ответ ссылку на элемент
  входного списка; последующее `result[-1][1] = ...` меняет данные вызывающего
  кода. Кладите копию. По той же причине — `sorted(...)`, а не `.sort()`.
- **Сравнение каждого с каждым «для надёжности».** Работает, но это O(n²),
  и важно понимать, почему после сортировки оно не нужно.
